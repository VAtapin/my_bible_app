# Bible Desktop — Моё приложение

Персональный продукт на базе Bible Desktop: пользователь выбирает только те
разделы, которыми действительно пользуется, получает единый профиль и может
работать с ним в браузере, Android и iOS — в том числе без интернета.

> PWA реализована на Vue. Полностью нативные Android- и iOS-клиенты создаются в
> `mobile/` на Jetpack Compose и SwiftUI с общей Kotlin Multiplatform-логикой.

## Идея

На старте выбирается язык. «Быстро настроить» одним нажатием включает все
разделы и молитвенные сборники, Азбуку, часы и календарь, затем открывает
«Сегодня» без мастера. Перевод Библии соответствует языку интерфейса.
Существующий профиль повторным открытием quick URL не заменяется.

«Настроить самому» сохраняет ручной выбор состава и переводов. Скачивание
офлайн-материалов и разрешение уведомлений остаются отдельными действиями.

После создания конфигурацию можно изменить через раздел
**«Настроить моё приложение»**. Ничего не требуется выбирать навсегда.

## Первый экран

Первый экран предлагает только три понятных пути:

- **Быстро настроить** — несколько вопросов и готовая основа;
- **Настроить самому** — выбор по тематическим разделам;
- **У меня уже есть приложение** — восстановление по ссылке, коду или аккаунту.

Полный каталог функций на первом экране не показывается. Он открывается только
после осознанного выбора ручного режима.

## Основные принципы

- mobile-first: основной сценарий рассчитан на телефон и управление касанием;
- progressive disclosure: на каждом шаге показываются только необходимые решения;
- offline-first: выбранные тексты и настройки доступны без сети;
- notifications by choice: уведомления включаются только после явного выбора;
- privacy by default: конфигурация хранит минимум персональных данных;
- one profile, multiple clients: один профиль используется в PWA, Android и iOS;
- existing API first: контент и бизнес-логика не дублируются в новом проекте.

## Планируемые клиенты

| Клиент | Назначение |
| --- | --- |
| PWA | Быстрый вход без магазина приложений, персональная ссылка, установка на главный экран |
| Android | Надёжный офлайн, локальные и push-уведомления, системная интеграция |
| iOS | Надёжный офлайн, локальные и push-уведомления, системная интеграция |

Нативные сборки должны давать самостоятельную ценность и не быть простой
WebView-обёрткой сайта.

## Технологический стек

- PWA: Vue 3, TypeScript, Vite, Pinia, Vue Router, IndexedDB и Service Worker;
- Android: Kotlin и Jetpack Compose;
- iOS: Swift и SwiftUI;
- общая мобильная логика: Kotlin Multiplatform, Ktor и kotlinx.serialization;
- данные: существующий типизированный Bible Desktop API;
- офлайн: платформенные базы за общими репозиториями.

Capacitor-оболочки, созданные на этапе веб-прототипа, больше не являются целевой
архитектурой устанавливаемых приложений. Они будут удалены после переноса и
проверки соответствующих сценариев в `mobile/`.

## Источник данных

Основное API находится в соседнем проекте:

```text
D:\Projekte\BibleDesktop
```

В существующем Laravel API уже предусмотрены, в частности:

- `GET /api/home`;
- `GET /api/translations`;
- `GET /api/translations/{code}/books`;
- `GET /api/translations/{code}/books/{book}/chapters/{chapter}`;
- `GET /api/prayers` и маршруты отдельных молитв;
- `GET /api/calendar/day`;
- `GET /api/liturgical/collections`;
- `GET /api/liturgical/works` и маршруты редакций текстов.

Новый проект является клиентом этого API. Новые серверные endpoints добавляются
в Bible Desktop только тогда, когда существующего контракта действительно
недостаточно для профилей, синхронизации или пакетного офлайн-обновления.

Базовый URL API для PWA хранится в одном файле
`config/api-base-url.txt`. Для смены основного домена достаточно изменить
эту одну строку и пересобрать web-клиент. Конкретная web-сборка может
временно переопределить адрес через `VITE_API_BASE_URL`.

**ЕДИНСТВЕННЫЙ API — BIBLEDESKTOP, ВКЛЮЧАЯ КАЛЕНДАРЬ.**
Основной проект API — `D:\Projekte\BibleDesktop`. Второго календарного API,
отдельной конфигурации его адреса и внешнего календарного клиента здесь нет.
Недостающие маршруты и поля дополняет чат проекта BibleDesktop по согласованию
с потребителями; приложение не рассчитывает церковные даты, посты и ранги.

Сетка использует `/calendar/month`, выбранный день — `/calendar/day`,
богослужебные тексты — `/calendar/service` того же основного API.
На главной месяц компактный; в разделе календаря есть день, неделя и месяц,
все памяти и праздники, знаки Типикона, значки поста, иконы и чтения.
Справочные тексты не выдаются за назначенный чин. Ключи, подмена Origin/Referer
и обход ограничений не используются; запросы отправляются с `credentials: omit`.
Только отсутствие сети/таймаут разрешают открыть явно сохранённые данные
BibleDesktop; ошибки доступа, лимитов или формата не маскируются старым ответом.
Сохранения прежнего внешнего источника не подставляются вместо BibleDesktop,
но личные данные и прежние записи IndexedDB не удаляются.

## Что входит в первый выпуск

- первый экран с быстрым и ручным режимами;
- выбор одного или нескольких переводов Библии;
- утренние и вечерние молитвы;
- молитвослов;
- церковный календарь и чтения дня;
- настройка уведомлений;
- персональная конфигурация приложения;
- восстановление конфигурации;
- офлайн-загрузка выбранных материалов;
- ручное обновление и отображение состояния офлайн-данных;
- изменение состава приложения после создания.

Часослов, Псалтирь и акафисты можно включить в первый выпуск после проверки
готовности соответствующего API и объёма офлайн-пакетов. ИИ, социальные функции,
сложные планы чтения и редактор собственных подборок не должны задерживать MVP.

## Разработка

Web-разработка использует Node.js 22. Нативный Android-проект использует Kotlin
2.4.20, Android Gradle Plugin 9.2.1, Gradle 9.4.1, JDK 25, compile/target SDK 37
и min SDK 26. Нативный iOS-проект использует SwiftUI и deployment target 16.0;
для его сборки требуется macOS с Xcode.

```bash
npm ci
npm run dev
```

Проверка типизации, модульных тестов и production-сборки:

```bash
npm run check
```

Сборка и тест общей мобильной логики и Android-приложения:

```powershell
cd mobile
.\gradlew.bat :sharedLogic:testAndroidHostTest :androidApp:assembleDebug
```

Подробности находятся в [mobile/README.md](mobile/README.md). На текущей рабочей
машине Android Studio, JDK 25, SDK 37 и эмулятор `BibleDesktop_API_37` уже
установлены.

Базовый адрес API берётся из `config/api-base-url.txt`. Для локального
или server-specific override используется `VITE_API_BASE_URL`; пример
находится в `.env.example`.

## Production PWA

Одна production-сборка PWA обслуживает четыре домена:

- `https://biblia-app.ru` по умолчанию открывает русский интерфейс;
- `https://bible-app.de` — канонический адрес немецкого интерфейса;
- `https://biblia-app.de` также по умолчанию открывает немецкий интерфейс;
- `https://bible-app.online` выбирает RU/DE/UK/EN по языку браузера.

Первый экран сразу предлагает языки с родными названиями: Русский, Deutsch,
Українська, English. Ссылки `/ru`, `/de`, `/uk`, `/en` явно задают язык и имеют
приоритет над сохранённым выбором; адрес без языка сохраняет обычное поведение.
Старт содержит месяц и краткую сводку выбранного дня ещё до создания профиля.
В портрете планшета храм занимает всю ширину, в альбомной ориентации — левую
половину. Телефон сохраняет последовательность hero → настройка → календарь.

Production build создаёт четыре статические языковые страницы с локализованными
Open Graph/Twitter-метаданными и JPEG-превью 1200 × 630. Messenger-ботам не нужен
JavaScript: например, `https://bible-app.online/uk` уже содержит украинские
заголовок, описание и изображение. Исходная композиция находится в
`tools/social-preview.html`, строки — в `config/social-pages.json`.
Превью сервисов могут оставаться в их собственном кэше после обновления.

Язык интерфейса не переименовывает корпус: для UK доступны существующий
`BQ_UKRAINE`, для EN — `BQ_ENGLISH_KJV_1769`. BibleDesktop пока не отдаёт английский
календарный корпус; EN использует русский календарный текст. Отдельный учебный плагин
«Азбука» сохраняет свои RU/DE/CU, с RU-резервом для UK/EN основного интерфейса.

Сохранённый ручной выбор пользователя имеет приоритет над языком
домена. Переключение на DE внутри production-приложения открывает
`bible-app.de`, а переключение на RU — `biblia-app.ru`, с сохранением маршрута,
query и hash. Все домены направлены на один каталог
`/var/www/vhosts/biblia-app.ru/httpdocs`; Document Root должен указывать на
`/var/www/vhosts/biblia-app.ru/httpdocs/dist`.

Первое развёртывание в уже созданном, но ещё не подключённом к Git каталоге:

```bash
cd /var/www/vhosts/biblia-app.ru/httpdocs && \
git init && \
git remote add origin https://github.com/VAtapin/my_bible_app.git && \
git fetch origin main && \
git checkout --track origin/main && \
export PATH="/opt/plesk/node/22/bin:$PATH" && \
npm ci && \
npm run build
```

Команда не удаляет существующие файлы. Если в каталоге есть стандартная
страница Plesk с именем, совпадающим с файлом репозитория, `git checkout`
остановится и потребует сначала вручную разобрать этот конфликт.

Обновление от пользователя Plesk домена `biblia-app.ru`:

```bash
cd /var/www/vhosts/biblia-app.ru/httpdocs && \
export PATH="/opt/plesk/node/22/bin:$PATH" && \
git pull --ff-only && \
npm ci && \
npm run build && \
tar -czf dist/azbuka-release.tar.gz -C azbuka-web/dist .
```

Основная версия создаётся в `dist`, самостоятельная «Азбука» — в
`azbuka-web/dist`. Домены обслуживают разные пользователи Plesk, поэтому
`scripts/deploy-production.sh` с прямой записью в обе папки здесь неприменим.
Не расширяйте межпользовательские права. Архив содержит только публичную сборку.

Затем от пользователя Plesk домена `bible-desktop.com`:

```bash
cd /var/www/vhosts/bible-desktop.com/my_app/azbuka-web/dist && \
azbuka_archive="$(mktemp /tmp/azbuka-release.XXXXXX)" && \
curl --fail --show-error --location \
  "https://biblia-app.ru/azbuka-release.tar.gz?v=$(date +%s)" \
  --output "$azbuka_archive" && \
tar --extract --gzip --file="$azbuka_archive" \
  --no-same-owner --no-same-permissions && \
test -s index.html && test -s sw.js && \
rm -f -- "$azbuka_archive"
```

Публичная папка отдельной «Азбуки» должна существовать. Старый checkout
`/var/www/vhosts/bible-desktop.com/my_app` не используется: источником обеих
сборок остаётся действующий checkout Biblia App. PHP, Composer и миграции
этому клиентскому проекту не нужны.

## Учебные плагины и главная

В настройке выбираются конкретные приложения, без дублирующего переключателя
«Обучение». «Азбука с цифирью»
работает внутри основной оболочки по `/education/azbuka`: буквы, цифирь,
тренировки и профиль используют те же исходники, что и самостоятельный сайт.
У каждой версии свой локальный прогресс в IndexedDB соответствующего origin;
автоматической синхронизации между доменами нет.

«Сегодня» показывает дату и старый стиль в скобках одним заголовком,
компактные часы с постоянно видимыми секундами при подключённой «Азбуке»,
случайный стих из настоящего текста Библии, календарную сводку, продолжение
чтения и учебный прогресс. Отдельного переключателя часов больше нет; старое
значение `showClock: false` не скрывает их при включённой «Азбуке».
Для календаря настраиваются пост/трапеза, памяти, чтения и краткий режим.
«Офлайн-горизонт» сохраняет полный день BibleDesktop, месячную сводку, служебные
тексты и небольшие изображения на 30 дней. Иконные превью имеют сторону до
320 px и размер до 80 KiB, без скачивания полных галерей. Для экономии трафика
BibleDesktop отдаёт их по существующему image-URL с `?preview=1`.
Счётчик увеличивается после записи в IndexedDB; рядом отображаются диапазон,
завершение, недостающие изображения/тексты или ошибка. Отмена сохраняет уже
записанные дни. Ошибки доступа не подменяются устаревшими данными.
Знаки Типикона и поста из BibleDesktop включены в PWA без изменения файлов:
пять SVG и восемь небольших PNG (каждый до 80 KiB). API по-прежнему определяет
знак для даты; клиент только сопоставляет точный адрес с оригинальным файлом.
Существующий service worker предкэширует их вместе с приложением, а офлайн-
горизонт сохраняет все знаки полной месячной сетки, не только выбранных 30 дней.
Cross-origin CORS статических SVG/PNG для этих известных файлов не требуется.
Неизвестные ресурсы продолжают загружаться с API; сбои отмечаются явно.
Загрузка календарных запросов последовательная, с паузами для лимита 30/мин;
429 повторяется один раз после Retry-After, без обхода серверного ограничения.
Пять основных кнопок: «Сегодня», «Библия», «Молитвы», «Календарь», «Ещё».
Логотип открывает главную, у чтения и «Азбуки» собственные нижние панели.
Читалка открывает точный стих, прокручивает к нему и выделяет его. Правый клик,
долгое нажатие и кнопки в подвале открывают действия: поделиться/скопировать
ссылку, поиск по Библии, заметка. Поиск использует существующий API и открывает
найденный стих внутри приложения. Заметки сохраняются в локальной IndexedDB
отдельно от скачанных текстов, без отправки на сервер. Аудио пока не подключено.

«Ещё» → «Оформление»: стандартный смешанный стиль и варианты по макетам 2 и 3.
Выбор сохраняется на устройстве независимо от настройки разделов.
Все варианты показывают настоящую икону дня и события из API; нажатие открывает
икону крупно внутри приложения. При нескольких иконах приоритет определяется
по точным привязкам каталога к памятям в порядке главенства дневного API.
В календаре можно выбрать день в сетке недели или месяца; все его памяти
показываются независимо от фильтра краткой сводки главной.
`npm run build` собирает обе версии; `npm run check` проверяет также общие
учебные тесты.

## Статус

PWA содержит клиентские этапы 1–5: конструктор, Библию, молитвы, календарь,
offline, уведомления и профиль. Для нативного направления создан новый KMP-
каркас: Android и iOS имеют отдельный платформенный UI, а первый общий клиент
загружает живой каталог переводов из production API с RU/DE-интерфейсом.
Android debug APK собран и проверен на API 37; iOS-сборка и проверка на
физических устройствах требуют macOS и дальнейшей реализации сценариев.

### Параллельное чтение двух переводов

В веб-читалке нажмите «Параллельное чтение», в Android — «Сравнить переводы».
Выберите второй перевод и режим: «Строка под строкой» или «Два окна — одно
под другим». Второй режим имеет отдельную прокрутку каждого окна; книга
и глава общие. Режим сохраняется на устройстве. Для выхода — «Один перевод».
Стихи сопоставляются по точным OSIS-ссылкам, книги — по каноническому
идентификатору. Отсутствующие стихи явно обозначаются. Веб сохраняет открытые
главы второго перевода в существующем офлайн-хранилище; Android использует
существующий OfflineContentRepository. Новых API и миграций нет.
