# Bible Desktop — Моё приложение

Персональное приложение на базе Bible Desktop: пользователь выбирает только те
разделы, которыми действительно пользуется, получает единый профиль и может
работать с ним в браузере, Android и iOS — в том числе без интернета.

> MVP реализован в общей Vue/Capacitor-кодовой базе. До публичного выпуска
> остаются нативные device-проверки, подписанные store-сборки и реальный пилот.

## Идея

Вместо перегруженного каталога пользователь проходит короткую настройку:

1. выбирает быстрый готовый набор или ручную настройку;
2. уточняет переводы Библии, молитвенные разделы и календарь;
3. выбирает нужные уведомления и время;
4. проверяет итоговый набор;
5. загружает выбранные материалы для офлайн-работы.

После создания конфигурацию можно изменить через раздел
**«Настроить моё приложение»**. Ничего не требуется выбирать навсегда.

## Первый экран

Первый экран предлагает только три понятных пути:

- **Быстро настроить** — несколько вопросов и готовая основа;
- **Настроить самому** — выбор по тематическим разделам;
- **У меня уже есть приложение** — восстановление по ссылке, коду или аккаунту.

Полный каталог функций на первом экране не показывается. Он открывается только
после осознанного выбора ручного режима.

## Основные принципы

- mobile-first: основной сценарий рассчитан на телефон и управление касанием;
- progressive disclosure: на каждом шаге показываются только необходимые решения;
- offline-first: выбранные тексты и настройки доступны без сети;
- notifications by choice: уведомления включаются только после явного выбора;
- privacy by default: конфигурация хранит минимум персональных данных;
- one profile, multiple clients: один профиль используется в PWA, Android и iOS;
- existing API first: контент и бизнес-логика не дублируются в новом проекте.

## Планируемые клиенты

| Клиент | Назначение |
| --- | --- |
| PWA | Быстрый вход без магазина приложений, персональная ссылка, установка на главный экран |
| Android | Надёжный офлайн, локальные и push-уведомления, системная интеграция |
| iOS | Надёжный офлайн, локальные и push-уведомления, системная интеграция |

Нативные сборки должны давать самостоятельную ценность и не быть простой
WebView-обёрткой сайта.

## Рекомендуемый стек

Предварительное направление, которое необходимо подтвердить техническим
прототипом:

- Vue 3;
- TypeScript;
- Vite;
- Capacitor для Android и iOS;
- Pinia для состояния;
- Vue Router;
- SQLite на мобильных платформах;
- IndexedDB для PWA;
- Capacitor Local Notifications и Push Notifications;
- Service Worker для PWA;
- Vitest и Playwright;
- собственный типизированный API-клиент Bible Desktop.

Такой стек согласуется с существующим Vue-фронтендом Bible Desktop и позволяет
поддерживать один продуктовый интерфейс, сохраняя нативные возможности платформ.
Окончательное решение принимается после проверки офлайна, уведомлений и сборок
на реальных iPhone и Android-устройствах.

## Источник данных

Основное API находится в соседнем проекте:

```text
D:\Projekte\BibleDesktop
```

В существующем Laravel API уже предусмотрены, в частности:

- `GET /api/home`;
- `GET /api/translations`;
- `GET /api/translations/{code}/books`;
- `GET /api/translations/{code}/books/{book}/chapters/{chapter}`;
- `GET /api/prayers` и маршруты отдельных молитв;
- `GET /api/calendar/day`;
- `GET /api/liturgical/collections`;
- `GET /api/liturgical/works` и маршруты редакций текстов.

Новый проект является клиентом этого API. Новые серверные endpoints добавляются
в Bible Desktop только тогда, когда существующего контракта действительно
недостаточно для профилей, синхронизации или пакетного офлайн-обновления.

## Что входит в первый выпуск

- первый экран с быстрым и ручным режимами;
- выбор одного или нескольких переводов Библии;
- утренние и вечерние молитвы;
- молитвослов;
- церковный календарь и чтения дня;
- настройка уведомлений;
- персональная конфигурация приложения;
- восстановление конфигурации;
- офлайн-загрузка выбранных материалов;
- ручное обновление и отображение состояния офлайн-данных;
- изменение состава приложения после создания.

Часослов, Псалтирь и акафисты можно включить в первый выпуск после проверки
готовности соответствующего API и объёма офлайн-пакетов. ИИ, социальные функции,
сложные планы чтения и редактор собственных подборок не должны задерживать MVP.

## Разработка

Требуется Node.js 22 или новее.

```bash
npm ci
npm run dev
```

Проверка типизации, модульных тестов и production-сборки:

```bash
npm run check
```

Синхронизация общей web-сборки с Android и iOS:

```bash
npm run cap:sync
```

Адрес API задаётся переменной `VITE_API_BASE_URL`; пример находится в
`.env.example`.

## Production PWA

PWA предназначена для `https://my.bible-desktop.com`. На сервере проект
располагается в `/var/www/vhosts/bible-desktop.com/my_app`, а document root
субдомена должен указывать на каталог `dist` внутри проекта.

Первое развёртывание в уже созданном, но ещё не подключённом к Git каталоге:

```bash
cd /var/www/vhosts/bible-desktop.com/my_app && \
git init && \
git remote add origin https://github.com/VAtapin/my_bible_app.git && \
git fetch origin main && \
git checkout --track origin/main && \
export PATH="/opt/plesk/node/22/bin:$PATH" && \
bash scripts/deploy-production.sh
```

Команда не удаляет существующие файлы. Если в каталоге есть стандартная
страница Plesk с именем, совпадающим с файлом репозитория, `git checkout`
остановится и потребует сначала вручную разобрать этот конфликт.

Последующие обновления выполняются короче:

```bash
cd /var/www/vhosts/bible-desktop.com/my_app && \
export PATH="/opt/plesk/node/22/bin:$PATH" && \
bash scripts/deploy-production.sh
```

Скрипт выполняет fast-forward pull, `npm ci`, production build и проверку
основных файлов PWA. PHP, Composer и миграции этому клиентскому проекту не нужны.

## Статус

Реализованы клиентские этапы 1–5: конструктор, Библия, молитвы, календарь,
offline, локальные уведомления, защищённый профиль, восстановление, экспорт и
удаление. Для подготовки выпуска добавлены privacy-экран, обезличенная локальная
диагностика, тест миграции IndexedDB и release/store/pilot-документация.
Android- и iOS-проекты используют общую кодовую базу; их подписанные сборки и
проверка на физических устройствах остаются обязательным внешним этапом.
