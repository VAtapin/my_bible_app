# PROJECT_STATUS

## Реализовано

- Vue 3/TypeScript PWA для `biblia-app.ru`, `biblia-app.de`, `bible-app.de`
  и `bible-app.online`. Поддомен `my.bible-desktop.com` удалён и не используется.
- RU/DE onboarding, выбор переводов, молитвенных разделов, календаря и конкретных
  учебных плагинов. Конфигурация сохраняется локально, старые профили совместимы.
- «Азбука с цифирью» работает внутри Biblia App по `/education/azbuka`:
  37 букв, контекстные примеры, цифирь 1–999, упражнения, локальный прогресс.
  Отдельный сайт `https://azbuka.bible-desktop.com` сохранён. Обе версии
  используют одни исходники из `azbuka-web/src`.
- Главная «Сегодня» оформлена по согласованным макетам: один заголовок с датой
  и старым стилем в скобках, компактные часы с живыми секундами при подключённой
  «Азбуке», случайный настоящий стих Библии, календарная сводка без повторных
  заголовков, продолжение чтения и видимая карточка учебного плагина.
- Часы при включённой «Азбуке» обязательны, даже если старый профиль содержит
  `showClock: false`. В настройке выбирается сам плагин, без второго переключателя
  «Обучение». Для календаря настраиваются пост/трапеза, памяти, чтения и краткость.
- Три оформления на выбор в «Ещё»: стандартное сочетает три макета, светлое
  соответствует варианту 2 (настоящая икона и евангельское чтение дня из API),
  тёплое — палитре варианта 3. Выбор сохраняется на устройстве.
- Логотип открывает главную. Основная нижняя панель всегда имеет пять кнопок:
  «Сегодня», «Библия», «Молитвы», «Календарь», «Ещё». Встроенная «Азбука» имеет
  свои пять разделов внизу, чтение — собственную панель по выбранному оформлению.
  В чтении работают выбор стиха, закладка, изменение размера текста и отправка
  ссылки/копирование; заметки и аудио пока не подключены и явно неактивны.
- В standalone «Азбуке» убрана большая приветственная шапка и поясняющие подписи
  часов; сохранены действия обучения, сами часы и показатели прогресса.
- Карточка буквы уменьшена вдвое в обеих версиях «Азбуки»; на телефоне знак
  и пояснение расположены рядом. Выбор оформления — три компактные плитки
  в одну строку с обычными радиокнопками; сохранение выбора проверено.
- Ponomar и его SIL OFL 1.1 поставляются локально в обеих PWA. Системная озвучка
  отключена, поскольку не читает церковнославянский Unicode корректно.
- Web-клиент поддерживает Библию, молитвы, календарь, offline-данные, уведомления
  и профиль. Android/iOS-код сохранён, в этой задаче нативные приложения не менялись.
- Ранее реализованы KMP API, Compose/SwiftUI экраны, Android-закладки и
  восстановление чтения; Android debug APK был собран и проверен на API 37.

## Важные решения

- Основной API — проект `D:\Projekte\BibleDesktop`.
  URL web API задаётся в `config/api-base-url.txt` и через `VITE_API_BASE_URL`.
- `biblia-app.ru` задаёт RU, `biblia-app.de` и `bible-app.de` — DE,
  `bible-app.online` — язык браузера. Сохранённый выбор имеет приоритет.
  Канонический немецкий адрес в переключателе — `https://bible-app.de`.
- Учебные продукты могут работать как встроенные плагины и самостоятельные
  приложения. Старая рекомендация обязательно отделить Web App в другой
  репозиторий больше не применяется к текущей интеграции.
- Прогресс «Азбуки» хранится в IndexedDB каждого origin отдельно. Обновление
  кода обоих сайтов не означает синхронизацию пользовательского прогресса.
- `npm run build` создаёт основную `dist` и `azbuka-web/dist`.
  `npm run check` проверяет типы, тесты обеих областей и обе production-сборки.
- Действующий серверный checkout:
  `/var/www/vhosts/biblia-app.ru/httpdocs`; основная публичная папка — `dist`.
- Подтверждённая публичная папка отдельной «Азбуки»:
  `/var/www/vhosts/bible-desktop.com/my_app/azbuka-web/dist`.
  Домены обслуживают разные пользователи Plesk: общий скрипт
  `scripts/deploy-production.sh` нельзя использовать для записи в обе папки.
  Основной пользователь собирает обе версии и публикует архив готовой «Азбуки»;
  пользователь BibleDesktop скачивает и распаковывает его в её публичной папке.
  Родительский старый проект `/var/www/vhosts/bible-desktop.com/my_app`
  не используется для Git или сборки и не удаляется.
- Production: Plesk Node.js 22. Для этих web-сборок PHP/Composer и миграции не нужны.
  Commit/push не является deployment; серверный скрипт запускает владелец.

## Текущее состояние и известные проблемы

- Локальная интеграция и обе production-сборки проверены. Публикация этих изменений
  на сервер и проверка HTTPS/service worker после неё ещё не выполнялись.
- Отдельную «Азбуку» обновлять от её собственного пользователя Plesk;
  права между пользователями не расширять.
- Автоматической синхронизации учебного прогресса между доменами нет.
- Немецкий молитвенный API ранее возвращал русский корпус; клиент фильтрует
  фактический язык и не выдаёт его за немецкий. Нужен импорт немецких материалов.
- Учебные тексты и переводы требуют редакторской проверки специалистом.
  Аудиопакет, титла/надстрочные знаки, очередь ошибок и дополнительные игровые
  режимы ещё не реализованы.
- iOS build требует macOS/Xcode. Нативные offline-пакеты, APNs/FCM,
  store-подпись и перенос Android-закладок в SwiftUI остаются отдельными задачами.
  Сейчас приоритет — web.
