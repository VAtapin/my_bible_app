# PROJECT_STATUS

## Реализовано / текущее состояние

- Веб/Android: два окна с независимыми переводом/книгой/главой/стихом и
  смещением, активное окно для общих команд, синхронизация по точной OSIS
  верхнего видимого стиха (не по пикселям), регулируемый разделитель,
  обмен местами, закрытие/возврат без потери места и сохранение режима.
  В каждом окне непрерывное чтение книги. Отсутствующее соответствие
  явно отмечается, место другого окна сохраняется. Выбор книги/главы,
  цифровой переход глава:стих, закладки, заметки/share и изучение используют
  фактический источник. Переключение в «стих под стихом» сохраняет места окон.
- Поиск стихов: точные слова/несколько слов, фраза, фрагменты, Стронг,
  словоформы; области всей Библии/заветов/Псалтири/книги, выбор нескольких
  переводов, страницы по 50, подсветка, точный переход и восстановление
  запроса/результатов. Вход из «Ещё» и читалки. Android: локальный SQLite
  индекс установленных текстов, фоновое построение с отменой, полный счётчик,
  повторное использование/обновление индекса по состоянию пакета; Snowball
  для RU/DE/EN (основы слов, е/ё, не словарная семантика). Лицензия в APK/About.
  Веб: серверный поиск словоформ с обозначенным приблизительным fallback;
  точные режимы проверяются по полному тексту, число означает показанные
  совпадения. Выбор книги фильтрует страницы по OSIS. Офлайн — сохранённые
  главы для всей Библии/Псалтири, словоформы RU/DE/EN и подсветка через
  лениво загружаемый Snowball JS. Области заветов офлайн требуют метаданных API.
- Веб/Android: непрерывная прокрутка книги через главы в обе стороны,
  подгрузка соседних глав, сохранение верхнего видимого стиха и смещения
  внутри него. Заголовок и толкования следуют за видимой главой; действия
  над стихами используют их фактическую главу. Добавление предыдущей главы
  сохраняет положение текста. Android использует виртуализированный список
  и установленные тексты без сети; веб загружает главы через прежний API/кэш.
  Ошибку продолжения можно повторить, редакция не подменяется.
- Веб/Android: раздел «Книги» из публичного API, поиск названия/автора,
  постраничные каталог и оглавление, полный текст, переходы между разделами,
  восстановление раздела/прокрутки. Есть контекстные толкования к книге,
  главе, стиху, диапазону текущей главы и видимым стихам; выбор до 30
  источников с поиском и сохранением, авторы/источники, раскрытие полного
  материала и устранение дублей по ID. Окно может следовать за верхним видимым
  стихом. Открытые страницы сохраняются офлайн; полного пакета источника нет.
  Каталог обновляется вручную; импорт толкований ещё идёт по уточнению владельца.
- Веб: Vue 3/TypeScript PWA, интерфейс RU/DE/UK/EN, персональная настройка,
  три оформления, Библия, молитвы, календарь, локальные заметки/закладки,
  уведомления, профиль и встроенная/standalone «Азбука» (37 букв, цифирь,
  упражнения/прогресс). Публичное название — Bible App; технические ключи,
  идентификаторы и API BibleDesktop не переименованы.
- Android: самостоятельный Jetpack Compose/KMP UI без WebView, пакет
  com.bibledesktop.myapp, debug отдельно (.debug). Храм, адаптивные раскладки,
  быстрый запуск, ручная настройка «Сохранить», язык интерфейса в настройках.
  Удобный выбор книги/главы прямо из читалки, точные ссылки/подсветка стиха,
  два режима сравнения, заметки/закладки/share, реальные cross-references/Strong,
  четыре локальных напоминания с явным изменением времени и About.
  Inter/Noto Serif/Ponomar/Monomakh встроены с OFL.
- 09.10.2026: **веб — «Включённые / Каталог», Android — «Загруженные / Каталог»**,
  поиск и фильтры группа → язык. Веб включает/отключает перевод без установки;
  Синодальный включён по умолчанию. Используется
  /translations?catalog=available (не короткий default и не непубличный all).
  Каталог растёт во время импорта, числа не зашиты. Группы — точные Glottolog

  Фильтры четырёх языков удалены только из выбора Библий.
- Над списком выбранных переводов постоянно доступен прямой вход в каталог:
  веб «Включить другие переводы», Android «Скачать другие переводы».

## Важные решения / deployment

- Deployment Bible App и azbuka.bible-desktop.com выполняется разными
  пользователями Plesk. Скрипт deploy-production.sh по умолчанию обновляет
  только Bible App в своём checkout; межпользовательского копирования нет.
  --with-azbuka отдельно создаёт публичный архив, который импортирует
  пользователь сайта «Азбуки» по README. Для изменений читалки обновление
  отдельной «Азбуки» не требуется. Её интерфейс в этой задаче не изменён.
- **ЕДИНСТВЕННЫЙ API — BIBLEDESKTOP, ВКЛЮЧАЯ КАЛЕНДАРЬ** (API_SOURCE.md).
  Исходники D:/Projekte/BibleDesktop, production https://bible-desktop.com/api.
  Этот чат API не изменяет; новые функции согласовываются с его чатом.
  Расчёты праздников/постов/рангов не дублируются. Только сеть/таймаут позволяют
  fallback; 401/403/429/invalid data не маскируются.
- PWA: /var/www/vhosts/biblia-app.ru/httpdocs, Document Root dist, Plesk Node.js 22.
  npm run check — типы/тесты/main+standalone build; npm run build создаёт также
  четыре share-страницы и отдельные Android privacy страницы.
  RU/DE домены biblia-app.ru/bible-app.de сохранены, bible-app.online — общий.
- API сервер /var/www/vhosts/bible-desktop.com/httpdocs — Plesk PHP 8.4,
  preview требует GD/WebP. Standalone Азбука:
  /var/www/vhosts/bible-desktop.com/my_app/azbuka-web/dist, другой Plesk-пользователь;
  перенос архива описан в README. Эта задача не меняет standalone UI.
- Commit/push не являются deployment. Production в этой задаче не обновлялся.

## Известные ограничения / далее

- Проверка/план и реализованный этап описаны в `docs/READER_STUDY_AUDIT.md`.
  В публичном API подтверждены книги, авторы, статьи и диапазоны; число

  импортирует отдельный чат BibleDesktop; по просьбе владельца ему отправлен
  запрос согласовать каталог/статьи/словоформы/ссылки/изображения и офлайн.
  В локальном API появились маршруты dictionaries; на production они ещё
  не проверены. Клиентский раздел словарей пока не подключён.
- Следующие блоки: история переходов, выбор диапазонов, пометки слов,
  подборки/заучивание, настройки отображения/жестов/избранных переводов,
  полные офлайн-модули, словари/карты после API. Диапазоны выбора через
  границу главы, внутренние ссылки статей и правила источников по книгам
  ещё не реализованы. Текущая панель постранично фильтрует статьи главы;
  «Показать ещё» явно показывает просмотренную часть, не обещает полноту.
  Для карт сначала существующие изображения с проверенными метками,
  географические слои — следующий этап. API здесь не изменяется.
- Источник не исправляем: KJV 1Samuel 2–8 и RU Daniel 13/14 были пустыми;
  новые модули могут иметь объединённые/пустые стихи. Не выдумывать текст.
  У API нет языковых семей; новые неизвестные коды консервативно попадают в «Другие».
- Неполная локализация календарного контента (icons/food/typikon могут быть RU);
  владелец запретил создавать отсутствующие переводы. EN календарь использует RU,
  standalone Азбука RU/DE/CU. Молитвы cu: один текст, cu-civil: нет;
  русские тексты не подменяют эти редакции.
- Синхронизация/перенос профиля исключены владельцем. Данные браузера локальны
  для origin; автоматического обмена доменами нет. Android Азбука/OCR/360°,
  аудио, APNs/FCM, полные молитвенные пакеты/Часослов пока не реализованы.
- App Links требует production assetlinks.json с Play App Signing сертификатом;
  последняя проверка возвращала HTML. Manifest готов, debug в association не включать.
- До Play: физический ARM64/авиарежим/перезагрузка/Play splits, права на тексты и
  изображения, анкеты Data Safety/IARC/аудитории/страны/цена и review политики.
  RELRO end graphics-path .so не 16-KB aligned: warning сохранён, строгий аудит
  отклоняет; прошлый x86_64 16-KB runtime проходил, ARM64 не проверен.
  Владелец ещё должен резервировать ключ независимо от Windows DPAPI.
- iOS build/проверки требуют macOS/Xcode. Safari/iPad и учебный корпус требуют проверки.
