## Важные решения

- PWA, Android и iOS развиваются в одной ветке продукта и общей кодовой базе;
  платформенные различия реализуются адаптерами.
- IndexedDB используется для PWA; мобильное хранилище будет подключено за
  интерфейсом `ChapterRepository` после device-проверки SQLite-библиотеки.
- Контент и бизнес-логика остаются в Bible Desktop; новый проект является
  клиентом его публичного API.
- Production-каталог проекта — `/var/www/vhosts/bible-desktop.com/my_app`,
  document root субдомена — `/var/www/vhosts/bible-desktop.com/my_app/dist`.
- Проект создаётся сразу на новом поколении: зафиксированы точные prerelease-
  версии Capacitor 9.0.0-alpha.6 и Local Notifications 9.0.0-alpha.2 вместе с
  AGP 9.2.1 и Gradle 9.4.1; переход через старый production-stack не планируется.
- Нативная версия приложения согласована с `package.json`: Android versionName
  и iOS MARKETING_VERSION равны `0.1.0`, build/versionCode — 1.
- Источник визуальной системы — `D:\Projekte\BibleDesktop\UI`; основные цвета:
  `#4A6B8A`, `#7DA1C2`, `#EDE6D6`, `#F7F5F1` и акцентный `#B99A5A`.
- Золотой используется только как небольшой декоративный акцент; основные
  поверхности и действия оформляются фирменным синим.
- Небольшая несекретная конфигурация хранится в localStorage под версионированным
  ключом `bible-desktop:profile:v1` и проверяется при чтении. Контент остаётся в
  IndexedDB/SQLite, а серверные секреты восстановления локально не хранятся.
- Пока сервер не отдаёт версионированные офлайн-манифесты, версия библейского
  пакета вычисляется по опубликованному составу книг и числу глав. Завершённой
  считается только загрузка, после которой сохранена метаинформация пакета.
- Календарная дата вычисляется в `Europe/Berlin`, гражданские дни добавляются
  через UTC-полудень, чтобы переходы летнего времени не сдвигали дату.
- Уведомления планируются как неточные (`isExactNotification: false`), чтобы не
  запрашивать избыточное разрешение Android на exact alarms; окно пересобирается
  при запуске и содержит не более 56 напоминаний.
- Долговременное хранилище содержит только ID и ревизию удалённого профиля;
  секрет живёт в `sessionStorage`, а персональная ссылка переносит его во
  fragment URL, который не отправляется веб-серверу.
- Язык интерфейса не ограничивает чтение: список выбранных переводов Библии и
  список языков молитв хранятся независимо. Первый перевод считается основным.
- Немецкий интерфейс начинается с существующего перевода Elberfelder, русский —
  с Синодального; пользователь может заменить основной и добавить переводы на
  других языках.

## Известные проблемы и открытые вопросы

- iOS-сборка требует macOS/Xcode и пока не запускалась.
- Не выбрана и не проверена SQLite-библиотека на физических устройствах.
- Локальное уведомление реализовано, но ещё не проверено на Android и iOS.
- В основном API пока нет версионированных offline-манифестов и пакетных
  endpoints для Библии и календаря.
- Полная загрузка перевода выполняет последовательные запросы глав; серверный
  пакетный endpoint с размером и контрольной суммой ещё нужен для production.
- Офлайн-календарь сейчас загружается последовательными запросами по дням; для
  выпуска желателен пакетный календарный endpoint.
- Серверный endpoint push-токенов готов, но получение токенов APNs/FCM и
  отправка удалённых push-уведомлений ещё не подключены и требуют нативной
  конфигурации Apple/Google.
- Привязка профиля к учётной записи оставлена опциональной: схема содержит
  `user_id`, но текущий клиент не подключает её до выбора общей auth-схемы.
- TestFlight, закрытый Google Play track и пилот с реальными пользователями не
  выполнялись: нужны аккаунты магазинов, подпись сборок, macOS/Xcode, физические
  устройства и участники.
- Автоматическая отправка диагностики намеренно отсутствует; пилотный
  пользователь экспортирует только агрегированную локальную сводку.
- В основном API пока отсутствуют немецкие молитвенные и богослужебные тексты.
  Endpoint молитв при запросе `language=de` возвращает русский fallback;
  клиент проверяет фактический `language_code` и не показывает русский текст как
  немецкий, но серверный fallback необходимо исправить при импорте корпуса.
