# PROJECT_STATUS

## Реализовано

- PWA на Vue 3/TypeScript работает как самостоятельный браузерный клиент для
  `https://my.bible-desktop.com`: конструктор приложения, RU/DE, выбор переводов,
  чтение, молитвы, календарь, offline, уведомления и профиль.
- Подготовлены web deployment-скрипт, privacy/store/release/pilot-документация и
  фирменные ресурсы Bible Desktop.
- Принято новое целевое решение для устанавливаемых клиентов: Android и iOS —
  полноценные нативные приложения без WebView; PWA остаётся отдельно.
- В `mobile/` создан Kotlin Multiplatform-проект на Kotlin 2.4.20, AGP 9.2.1 и
  Gradle 9.4.1.
- Созданы отдельные платформенные интерфейсы: Jetpack Compose для Android и
  SwiftUI для iOS. Общими являются только API, модели и прикладная логика.
- Первый общий вертикальный сценарий загружает список переводов напрямую из
  production API, поддерживает фильтры всех/RU/DE переводов, состояния загрузки,
  пустого результата и ошибки.
- Фактический объект `language` production API зафиксирован в общей модели и
  покрыт unit-тестом с языковым query-параметром.
- Первый нативный экран локализован на русский и немецкий по системному языку,
  использует фирменную палитру и существующую иконку приложения.
- Создан SwiftUI Xcode-проект с подключением общего Kotlin-фреймворка,
  deployment target iOS 16.0 и bundle ID `com.bibledesktop.myapp`.
- Нативный Android APK собран, установлен и запущен на эмуляторе API 37;
  production-каталог и немецкий фильтр проверены визуально.

## Текущее состояние

PWA остаётся рабочим браузерным приложением. Новая нативная ветка архитектуры
подтверждена рабочей Android-сборкой и живым API-запросом. iOS-исходники и Xcode-
проект подготовлены, но не могут быть собраны в текущей Windows-среде.

`mobile/` пока содержит архитектурный фундамент и первый экран, а не полный
готовый store-релиз. Старые `android/` и `ios/` Capacitor-проекты временно
сохранены как проверяемая исходная реализация до переноса необходимых функций;
они больше не являются целевыми мобильными приложениями.

## Важные решения

- PWA, Android и iOS — три клиента одного Bible Desktop API, а не один web UI в
  трёх оболочках.
- Android UI пишется на Jetpack Compose, iOS UI — на SwiftUI.
- Kotlin Multiplatform используется для сетевого клиента, моделей, репозиториев
  и тестируемых use cases; платформенный UI не разделяется.
- Bundle/application ID обеих платформ — `com.bibledesktop.myapp`; текущая
  версия — `0.1.0` (build 1).
- Android: min SDK 26, compile/target SDK 37, JDK 25. iOS: minimum 16.0.
- Язык интерфейса и языки читаемого контента независимы. Локализация начинается
  с RU/DE, а переводы Библии выбираются из полного каталога API.
- Источник визуальной системы — `D:\Projekte\BibleDesktop\UI`; основные цвета:
  `#4A6B8A`, `#7DA1C2`, `#EDE6D6`, `#F7F5F1`, акцент `#B99A5A`.
- Текущий экран является проверкой архитектуры. Финальный UI будет собран по
  согласованному пользовательскому Figma/макету и адаптирован под обе платформы.
- Секреты подписи Android/iOS не хранятся в Git. Google Play App Signing и Apple
  Developer credentials настраиваются отдельно в аккаунтах и защищённом backup.

## Известные проблемы и открытые вопросы

- Полный набор нативных экранов ещё не реализован: первый запуск, «Сегодня»,
  чтение, молитвы, календарь, offline, уведомления, профиль и настройки предстоит
  переносить вертикальными сценариями.
- Нужен финальный UI/Figma как минимум для пяти ключевых экранов; текущая
  визуальная версия не считается утверждённым дизайном.
- iOS-сборка, Swift/Kotlin interop и подпись требуют macOS/Xcode и пока не
  проверены.
- Нативное офлайн-хранилище и миграции ещё не реализованы.
- APNs/FCM, локальные уведомления, deep links и store-подпись ещё не подключены
  к новой нативной реализации.
- В основном API пока нет версионированных пакетных endpoints для эффективной
  полной offline-загрузки.
- Немецкий корпус молитв и богослужебных текстов ещё требуется импортировать в
  основной Bible Desktop API; русский fallback нельзя показывать как немецкий.

## Рекомендуется следующим

Получить согласованный UI/Figma и реализовать нативный первый запуск: выбор языка
интерфейса, быстрый/ручной режим и независимый выбор одного или нескольких
переводов. После этого добавить навигацию каталог книг → глава → чтение →

выполнить первую iOS debug-сборку, чтобы рано подтвердить Swift/Kotlin interop.
