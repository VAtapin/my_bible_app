# Bible Desktop Native Mobile

Полностью нативные клиенты Bible Desktop. Здесь нет WebView и не встраивается
PWA.

## Архитектура

- `androidApp` — Android UI на Jetpack Compose;
- `iosApp` — iOS UI на SwiftUI;
- `sharedLogic` — модели, Ktor API-клиент и Swift-friendly loaders на Kotlin
  Multiplatform;
- production API — `https://bible-desktop.com/api`.

Идентификатор обеих платформ: `com.bibledesktop.myapp`. Текущая версия:
`0.1.0` (build 1).

Android debug имеет отдельный идентификатор `com.bibledesktop.myapp.debug`
и название «Bible Desktop · Тест». Он не заменяет release-приложение и не
использует его сохранённые данные. Автоматическая миграция данных старой
Capacitor-версии пока не реализована.

## Реализованные сценарии

- интерфейс RU/DE/UK/EN, язык выбирается сразу на старте;
- стартовый hero с оригинальным храмом: вся ширина телефона/портретного
  планшета, левая половина широкого альбомного окна;
- месяц BibleDesktop и сводка дня до настройки и на «Сегодня»;
  выбранная дата 22sp/старый стиль 16sp над сеткой без дубля ниже; повторный
  заголовок календаря и «Сегодня» над цитатой убраны. Иконка возвращает к текущему
  дню; нажатие на название месяца открывает прямой выбор месяца/года 1900–2100;
- быстрый запуск одним нажатием: все работающие нативные разделы
  (Библия/молитвы/календарь/изучение/напоминания), перевод языка интерфейса плюс
  CU/CU-civil. Напоминания изначально выключены: настройка и разрешение отдельно;
- ручная настройка сохранена;
- выбор разделов и нескольких переводов независимо от языка интерфейса;
- экран «Сегодня» с составом приложения;
- Библия: перевод → книга → глава → чтение, размер текста, закладки, share;
  выбор книг: закреплённый поиск по названию/сокращению, кнопки «Все»/Заветов,
  карточки с числом глав; на планшете адаптивная сетка вместо длинной колонки.
  Все переводы каталога доступны без возврата в мастер; полные названия и языки,
  прямо в читалке есть отдельные кнопки выбора книги и главы; окно использует тот же
  каталог/поиск и сетку глав. Выбор применяется после главы, отмена сохраняет место.
  Названия книг/заголовок главы используют шрифт редакции (Ponomar CU, Monomakh CU-civil).
  Переход к точному стиху подсвечивает его, в том числе в сравнении двух переводов;
  общий диалог с поиском перевода/языка. Смена перевода очищает поиск. Возврат из книги сохраняет
  фильтр/поиск через SaveableStateHolder. Поиск локальный,
  использует существующий полученный/сохранённый каталог без новых запросов API;
  стихи имеют естественную высоту, действия открываются одной кнопкой меню.
  Доступно выделение/копирование текста. На телефоне используется доступная
  ширина, на широком планшете мера чтения ограничена 840 dp; нижние кнопки
  собраны в центре. При смене главы чтение начинается сначала;
- сравнение двух переводов: кнопка в читалке, второй перевод из полного каталога,
  на телефоне тексты последовательно, на планшете две колонки с общей прокруткой.
  Книга определяется по canonical OSIS, стихи сопоставляются по точным OSIS-ссылкам,
  отсутствующие соответствия обозначены явно. Названия/порядок строк не являются
  идентификаторами; различия нумерации редакций не скрываются. Шрифт каждой редакции
  свой, размер общий; выбранный второй перевод сохраняется. Back закрывает сравнение;
- «Ещё → Библия без сети» и кнопка в читалке: полный выбранный перевод по каталогу
  BibleDesktop, книги/главы в том же OfflineStore. Несколько переводов по очереди,
  выбор Wi-Fi-only, WorkManager, прогресс committed глав/размер, отмена/продолжение.
  Работа идёт ограниченными шестиминутными порциями с атомарным checkpoint;
  после перезапуска проверяются реальные файлы глав, не только счётчик.
  429/5xx/Retry-After повторяются, ошибки доступа/данных не подменяются текстом.
  «Готово» только при наличии всех непустых глав. Пустые ответы API перечисляются
  отдельно; остальные главы скачиваются, повторное продолжение проверяет пробелы.
  KJV 1Samuel 2–8 в публичном API возвращаются с verses=[]/verses_count=0.
  Русский каталог объявляет 1191 главу, но Daniel 13/14 также пусты; 1189 с текстом.
  По решению владельца API не изменяется, отсутствующий текст не выдумывается.
  Словари/параллельные места не входят в этот пакет. Общий предел store 256 MiB;
- кнопка с домиком в Библии, молитвах и календаре сразу открывает «Сегодня»;
  обычная кнопка «Назад» сохраняет последовательный возврат;
- Android: каталог полных закладок, открытие сохранённого места и автоматическое
  продолжение последней главы;
- Отправка стиха из читалки и закладок: текст, ссылка на место и единый HTTPS
  адрес `https://bible-app.online/reader?translation=...&book=...&chapter=...&verse=...`.
  Native VIEW открывает точный перевод/стих до настройки, выделяет его; проверяет
  наличие текста до изменения места чтения. Повторная ссылка обновляет activity,
  а пересоздание не возвращает к исходному стиху после смены главы;
- Android: заметка к стиху, создание/редактирование, список в «Ещё», открытие
  главы, подтверждаемое удаление. Локальный version1 JSON в существующих
  SharedPreferences профиля, фоновое чтение/commit записи. Отмена не сохраняет
  черновик, повреждённые данные не перезаписываются; ключи закладок совместимы;
- Android: «Изучение Библии» с пояснениями параллельных мест, Стронга и заметок,
  кнопка выбора места открывает каталог напрямую. «Изучить стих» в меню читалки: настоящие
  `/verses/{id}/cross-references`, `/verses/{id}/strong-tokens?translation=...`,
  `/strong/{number}?verse=...` из BibleDesktop. Используется ID стиха из API.
  OSIS определяет книгу выбранного перевода; переход прокручивает к стиху,
  Back возвращает к источнику. Подключены существующие локальные заметки.
  Открытые материалы сохраняются в OfflineStore с разделением переводов;
  весь словарь не скачивается. Нет вымышленных статей/толкований;
- Android: четыре ежедневных локальных напоминания (утро/вечер/чтение/календарь),
  переключатели и время, version1 JSON в существующем профиле. Inexact
  AlarmManager без разрешения точных будильников; Android может задержать
  доставку. POST_NOTIFICATIONS запрашивается только при явном сохранении
  включённого расписания; общий запрет и блокировка канала учитываются.
  Расписание восстанавливается при запуске, после boot/time/timezone/package
  changes; после force-stop нужен запуск. Уведомление открывает нужный раздел,
  не раскрывает личные стихи/заметки; есть отмена категории и дедуп за день;
  время меняется явной кнопкой с часами и подписью «Изменить время», затем «Сохранить»;
- молитвы: независимый выбор языка текста/редакции → чтение, размер текста, share;
  для CU/CU-civil показано количество текстов в полученном каталоге, без подмены русскими;
- Ponomar для CU и Monomakh для CU-civil встроены вместе с OFL; HTML молитв
  преобразуется в текст без WebView, источник не выводится. Вступление тоже
  очищается от HTML: пустое `<p></p>`/`&nbsp;` не выводится и не оставляет отступ.
  При отправке молитвы передаётся текст, не HTML;
- Inter встроен для интерфейса, Noto Serif — для обычного чтения и заголовков.
  Это стабильная Android-типографика, не системная подстановка Roboto/Serif
  и не копия браузерной Georgia. Оба вариативных шрифта взяты без изменения из
  [Google Fonts Inter](https://github.com/google/fonts/tree/main/ofl/inter) и
  [Noto Serif](https://github.com/google/fonts/tree/main/ofl/notoserif), лицензии
  OFL включены в assets. Шрифт CU/CU-civil выбирается по редакции текста,
  независимо от языка интерфейса. Подписи икон используют отдельный размер
  текста и более широкие карточки вместо прежней узкой колонки;
- церковный календарь: месяц и неделя (включая переход между месяцами), старый
  стиль, пост, памяти и чтения. Иконы в порядке BibleDesktop, только превью в
  списках; большая галерея со свайпом и стрелками. Пять знаков Типикона и восемь
  пищевых/поминальных отметок встроены, сетка использует назначенные API знаки;
- богослужебные тексты дня: независимый выбор редакции, CU-civil по умолчанию,
  раскрываемые тексты и масштаб. Название Часа/пояснение приложения/сообщение
  properCoverage не выводятся по просьбе владельца. API содержит календарные
  вставки; полное последование из Часослова в Android ещё не подключено.
- Android-офлайн: открытые главы, каталоги, молитвы, месяцы, дни и тексты служб
  сохраняются атомарно в noBackupFilesDir, а не в очищаемом системном кэше.
  Локальные данные читаются сразу; старше суток обновляются в фоне при сети
  и показываются обновлёнными при следующем открытии. Неизвестная схема не
  перезаписывается, запись ограничена 5 MiB на JSON и 256 MiB суммарно;
- «Ещё → Без сети»: WorkManager-пакет текущего и следующих 29 дней, месяцы,
  CU-civil тексты дня и первое API-превью каждой разрешённой к хранению иконы
  (до 384 KiB / 1024 px). Большие оригиналы не входят в пакет. Есть Wi-Fi-only,
  счётчик дней, ожидание/готово/ошибка, отмена и продолжение по атомарным
  checkpoints. Повторная новая загрузка обновляет данные пакета. Запросы
  календаря ограничены до 24/мин с запасом к серверному лимиту 30/мин;
  429/5xx и Retry-After учитываются без изменения серверных ограничений.

Android-сценарии проверены на эмуляторе API 37 с production API. SwiftUI-код
требует первой сборки и проверки на macOS.

## Android

### Ссылки Android App Links

В manifest заявлен только `/reader` на `bible-app.online`, HTTP/HTTPS; отправка
всегда использует HTTPS. Без установленного приложения это обычная ссылка веб-читалки.
Автоматическое открытие установленного release APK требует публичного
`https://bible-app.online/.well-known/assetlinks.json`: relation
`delegate_permission/common.handle_all_urls`, namespace `android_app`, package
`com.bibledesktop.myapp` и SHA-256 сертификата **подписи приложения**.
Для Google Play использовать App Signing certificate, не upload certificate.
Ключ подписи не публикуется и не хранится в Git.

На 09.10.2026 этот URL возвращает HTML, не Digital Asset Links JSON. Поэтому
автоматическое открытие через браузер ещё не подтверждено; сайт здесь не менялся.
Реальное получение VIEW cold/warm и навигация проверены отдельными тестами;
это не заменяет проверку домена. Debug-пакет отдельный и в production association
не добавлялся. После выбора подписи нужен отдельный серверный шаг и проверка
`adb shell pm get-app-links com.bibledesktop.myapp` на установленном release.

[Официальная настройка association](https://developer.android.com/training/app-links/configure-assetlinks).

Требуются JDK 25, Android SDK 37 и Android Studio 2026.1.4 или новее.

Из каталога `mobile`:

```powershell
$env:JAVA_HOME='C:\Program Files\Android\Android Studio\jbr'
$env:ANDROID_HOME='C:\Users\atapi\AppData\Local\Android\Sdk'
.\gradlew.bat :sharedLogic:testAndroidHostTest :androidApp:assembleDebug
```

Debug APK:
`androidApp/build/outputs/apk/debug/androidApp-debug.apk`.

Выбор книг: 27 релевантных тестов BookPicker (11), NativeSmoke (7), ReaderLayout (9).
Проверены поиск/сокращения/диакритика/пустой результат, Заветы, отсутствие

В реальном API-сценарии поиск сохранился после книги/главы, заметки и пересоздания
activity. Сборка и lint без ошибок; четыре снимка выбора просмотрены.

Офлайн-пакет требует несколько минут: день считается готовым только после
сохранения текста, службы и всех доступных для локального хранения превью.
Если права на локальное хранение иконы не разрешены API, её изображение в
пакет не включается. В офлайн-галерее доступно сохранённое первое превью,
остальные варианты требуют сети. Данные переживают обычное закрытие приложения;
удаление приложения удаляет и его локальные данные.

Это ещё не полная паритетная версия PWA. Нативная Азбука и восстановление профиля
пока не реализованы. Английский интерфейс явно
помечает русский календарный корпус. Часы/случайный стих главной, массовая
загрузка молитвенных сборников, управление размером пакетов,
синхронизация и миграция прежних данных требуют отдельных реализаций.
Физический авиарежим/перезагрузка телефона и восстановление фоновой задачи
после перезагрузки ещё не проверены; механизм WorkManager подключён.

Изучение/напоминания: 47 разных релевантных Android-тестов прошли отдельными
наборами на API 37, 12 sharedLogic host-тестов, assembleDebug и lintDebug.
Проверены реальные GET study, переход John 3:16 → 1John 4:10 → Back,

Bundle не разделяет языковые ресурсы: все четыре языка остаются доступны
без сети независимо от языка устройства. Store signing не настроен.

Сравнение/целые переводы: 47 разных instrumentation-проверок в отдельных
наборах (финальный короткий набор 46/46), 15 sharedLogic host-тестов,

снимок пакета с отсутствующей главой. Другие целые переводы и физическая
перезагрузка не проверены; недостающие тексты API здесь не исправлялись.

## iOS

Открыть `iosApp/iosApp.xcodeproj` на macOS в Xcode. В локальной копии указать
Apple Developer Team для target `iosApp`; сертификаты и signing secrets в Git не
добавлять. Xcode вызывает `:sharedLogic:embedAndSignAppleFrameworkForXcode` перед
сборкой. Минимальная версия iOS — 16.0.

## Подтверждённое ограничение API

На 09.10.2026 `/api/prayers?language=cu` содержит один текст cu («Отче наш»),
для cu-civil нет записей этой редакции. Русские записи в ответе — резерв источника,
они не выдаются за выбранную редакцию. Android показывает фактический размер
каталога; отсутствующие тексты не создаются и API здесь не изменяется.

На 18 сентября 2026 года `/api/prayers?language=de` возвращает русские записи.
Клиенты фильтруют ответ по фактическому `language_code`, поэтому русские молитвы
не выдаются за немецкие. Немецкий корпус должен быть импортирован на стороне
основного Bible Desktop API.
