# Материалы изучения и офлайн-атлас

Веб использует существующую IndexedDB; Android — локальные файлы и SQLite,
установку через WorkManager. Пакеты материалов отделены от переводов и
личных данных. API публикует только действительно собранные пакеты:
`GET /api/offline/packages`. Пока сервер не выполнил `bible:offline:build`,
каталог пакетов может быть пустым. Кэш просмотренного материала не считается
установленным полным источником.

Манифест содержит `id`, `kind`, `version`, `bytes`, `sha256`, `url`.
Поддерживаются dictionary, commentary, strong, cross_references. ZIP содержит
`module.json`, таблицы JSONL и файлы материала. В пакете перекрёстных ссылок
используются `sources.jsonl` и `references.jsonl`, таблицы entries нет.
Новые наборы дополнительно содержат необязательные
`versification_profiles.jsonl`, `versification_assignments.jsonl`,
`versification_map_sets.jsonl`, `versification_map_entries.jsonl`.
Пустые или отсутствующие таблицы не подтверждают нумерацию. Клиент допускает
предпросмотр только при доказанном назначении профилей, опубликованной версии
карты с происхождением, SHA-256 и проверяющим, и однозначных свидетельствах
для обоих сохранённых OSIS-адресов. Карта с другой целью не меняет ссылку молча.
Стабильные идентификаторы и числовые API aliases индексируются вместе с
версией. Фактическая OSIS-ссылка имеет приоритет над устаревшим числовым ID.

Загрузчик проверяет размер, SHA-256, идентичность модуля, структуру ZIP и
данные перед переключением установленной версии. Прерванная загрузка
продолжается с проверкой ответа Range. Новый индекс сначала создаётся
отдельно; отмена или ошибка сохраняет прежнюю версию. Удаление одного модуля
затрагивает только его файлы/индекс. Личные заметки, подборки и пометки
остаются в отдельном хранилище.

Изображения толкований перечислены в `media.jsonl`: стабильный SHA-256,
числовой API alias, MIME, размер и путь `media/{sha256}.{ext}`. Аннотация
статьи обязана указывать тот же файл и модуль. Перед установкой и чтением
проверяются контрольная сумма, размер, сигнатура и принадлежность; непроверенный
URL или отсутствующий companion-файл не загружается как иллюстрация.
Старые пакеты толкований без медиа остаются совместимыми.

Веб-индекс расширяет прежнюю базу до версии 4, добавляя индексы записей
по пакету, таблице, стабильному/API ID, OSIS, родителю и словоформе.
Android индексирует те же связи в SQLite. Толкования и словари читаются
из установленных полных пакетов без сети; для текста связанного библейского
стиха требуется также сохранённая глава или установленный перевод.

## Географические данные

`public/data/bible-geo.json` и Android `assets/data/bible-geo.json` содержат
одинаковый снимок: 1 342 объекта, опубликованные варианты расположения,
точные ссылки источника, 128 колец береговой линии и схему первого
путешествия Павла. Карта не обращается к стороннему серверу тайлов.
Веб включает снимок в PWA precache, Android поставляет его в APK.

Источники:

- [OpenBible.info Bible Geocoding](https://github.com/openbibleinfo/Bible-Geocoding-Data),
  CC BY 4.0, revision `7eb18a5ee62f27b9b93bd6689ea272d76dd23b8f`.
- [Natural Earth](https://github.com/nvkelso/natural-earth-vector), public domain,
  revision `ca96624a56bd078437bca8184e78163e5039ad19`.
- [OpenStreetMap contributors](https://www.openstreetmap.org/copyright),
  ODbL 1.0 для географических данных, указанных исходным набором.

`scripts/build-bible-geo.mjs` воспроизводит снимок из `ancient.jsonl`,
`land.geojson` и `OpenBible-CC-BY-4.0.txt` в указанном каталоге. Входные
SHA-256 закреплены в скрипте; изменение источника требует отдельной проверки.
Скрипт сохраняет исходные подписанные оценки, не преобразуя их в вероятности.
Координаты отсутствующих мест не создаются; одноимённые объекты остаются
разными ID. Линии маршрута соединяют засвидетельствованные остановки
Деян. 13–14 и не изображают достоверно восстановленные древние дороги.

Система ссылок OpenBible — English Protestant Bible. Автоматическое
сопоставление с неизвестной системой нумерации редакции не выполняется.
Пользователь может явно включить фильтр по исходным OSIS, прочитав пояснение.
`verse-locations` разрешает фактически сохранённое место в модуле, но само
по себе не доказывает смысловое соответствие между MT/LXX и другими системами.
Проверенные соответствия требуют профиля, provenance и версионированной карты.

Исходные изображения имеющихся атласов показываются отдельно через словарный
контракт с масштабированием. Если изображение не содержит опубликованных
координат объектов, маркеры на нём не придумываются.
