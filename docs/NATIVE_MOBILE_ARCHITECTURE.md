# Нативные приложения Android и iOS

## Решение

PWA остаётся самостоятельным браузерным клиентом на
`https://my.bible-desktop.com`. Устанавливаемые приложения разрабатываются
отдельно как настоящие платформенные интерфейсы:

| Слой | Android | iOS | Общая часть |
| --- | --- | --- | --- |
| Интерфейс | Jetpack Compose | SwiftUI | нет |
| Навигация и платформенное поведение | Android SDK | iOS SDK | только правила сценариев |
| API и модели | Kotlin/JVM | Kotlin/Native | Kotlin Multiplatform |
| Локальные данные | платформенный драйвер | платформенный драйвер | репозитории и схемы |

WebView и Capacitor не входят в целевую архитектуру мобильных приложений.
Существующие каталоги `android/` и `ios/` временно сохранены как предыдущий
проверенный прототип, пока новая нативная реализация не заместит необходимые
сценарии. Новая реализация находится в `mobile/`.

## Границы общей логики

Общая Kotlin Multiplatform-часть отвечает за:

- контракты Bible Desktop API;
- HTTP-клиент, декодирование и классификацию ошибок;
- правила профиля и выбранного контента;
- репозитории офлайн-данных и синхронизацию;
- тестируемые use cases.

Общая часть не должна содержать платформенный UI. Android и iOS получают одни и
те же данные, но отображают их нативными компонентами.

## UI до получения финального макета

Временный экран использует фирменную палитру Bible Desktop и существующую
иконку, но не считается финальным дизайном. Для продолжения нужны как минимум
макеты следующих состояний:

1. первый запуск и выбор языка интерфейса;
2. главный экран «Сегодня»;
3. каталог и выбор переводов Библии;
4. выбор книги/главы и чтение главы;
5. настройки профиля, языков и офлайн-данных.

Один общий Figma-макет достаточен. Системные различия навигации, размеров зон
касания, accessibility и диалогов адаптируются отдельно для Android и iOS.

## Последовательность реализации

1. Нативный каркас и общий production API-клиент.
2. Первый запуск, RU/DE и локальная конфигурация.
3. Каталог переводов, книги, главы, чтение и закладки.
4. Молитвы, богослужебные тексты и календарь.
5. Офлайн-хранилище и управляемая загрузка пакетов.
6. Локальные уведомления и deep links.
7. Профиль/синхронизация, accessibility, подпись и store-сборки.

Каждый пункт доводится до рабочего вертикального сценария на обеих платформах,
а не переносится из веба целиком.
