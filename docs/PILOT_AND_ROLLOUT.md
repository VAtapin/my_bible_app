# Пилот, rollout и rollback

## Пилот

Первая группа: 10–20 пользователей, отдельно iOS и Android, не менее семи дней.
Каждый участник получает короткий сценарий, ссылку на privacy policy и способ
сообщить проблему. Никакие реальные персональные ссылки не прикладываются к
тикетам; при необходимости участник копирует только обезличенную сводку из
экрана «Диагностика».

Проверяем:

- долю завершивших конструктор среди открывших его;
- успешность открытия сохранённого контента после выключения сети;
- число успешных полных загрузок и категорию ошибок загрузки;
- понятность запроса уведомлений и правильность переходов;
- восстановление на втором устройстве и последующее удаление тестового профиля;
- отсутствие потери данных после обновления RC.

Цели пилота:

- не менее 80% завершений конструктора;
- 100% участников открывают хотя бы одну ранее сохранённую главу offline;
- 0 потерь локальных данных при обновлении;
- 0 утечек секретов, токенов или пользовательского содержания;
- 0 критических падений запуска;
- все блокирующие ошибки воспроизводимы и исправлены до production.

## Реестр проблем

Для каждой проблемы фиксировать версию, платформу/версию ОС, шаги, ожидаемое и
фактическое поведение, категорию из локальной диагностики и результат повтора.
Не прикладывать тексты молитв/поиска, profile secret, recovery code и push token.

Приоритеты:

- P0: потеря данных, уязвимость, падение запуска, невозможность удалить данные;
- P1: не работает offline, восстановление или уведомления у значимой группы;
- P2: локальный UI/контентный дефект без потери сценария.

## Поэтапный выпуск

1. PWA на `my.bible-desktop.com` после server API и миграций.
2. TestFlight и внутренний Google Play track для команды.
3. Закрытый пилот 10–20 человек.
4. Production 10% при отсутствии P0/P1 в течение 48 часов.
5. Production 50% после ещё 72 часов стабильности.
6. 100% после семи дней стабильности и проверки удаления/экспорта.

Проценты применимы к управляемому phased rollout магазина. PWA выкладывается
атомарно, поэтому для неё сначала проверяется отдельный preview/RC URL или
локальный production build.

## Rollback

Клиент:

- остановить phased rollout или снять проблемный track;
- PWA вернуть к предыдущему проверенному commit и пересобрать;
- не понижать IndexedDB/SQLite schema и не удалять новые stores;
- сохранить чтение старых конфигураций и очередей минимум один release cycle.

Сервер:

- новые поля и endpoints добавляются совместимо; клиент посылает schema version;
- при проблеме отключить новые операции на уровне маршрута/feature flag, не
  удаляя таблицы и профили;
- не откатывать destructive migration без backup и проверенного восстановления;
- старый профильный контракт сохранять, пока активны клиенты соответствующей
  версии.

После rollback повторить smoke test чтения, offline, профиля и удаления данных.
