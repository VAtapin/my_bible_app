## Реализованный этап: книги и контекстные толкования

- Веб/Android используют подтверждённые публичные API книг, оглавлений,
  разделов и источников толкований. Поиск названия/автора, все страницы
  каталогов/оглавлений, полный текст/автор/источник, соседние разделы,
  восстановление раздела и прокрутки. Вход «Книги» находится в «Ещё».
- Толкования открываются к книге, главе, верхнему видимому стиху, видимым
  стихам или выбранному диапазону текущей главы. Список источников имеет
  поиск, выбор до 30 и сохраняется. Панель рядом с Библией на широком вебе,
  под Библией на телефоне/Android; в Android также из прежнего VerseStudy.
- Используется канонический slug из `/canons/{code}/books`, найденный по
  OSIS, а не предположение, что slug редакции совпадает с каноном.
  Статьи главы загружаются страницами по 10 и фильтруются по пересечению;
  «Показать ещё» указывает просмотренную часть. Статья не дублируется по
  количеству выбранных стихов. Текст диапазона не обрезается.
- Открытые страницы/статьи сохраняются в прежних хранилищах. Веб fallback
  допускается только при offline/timeout, Android при отсутствии сети или
  IOException. Ошибки HTTP/формата не подменяются сохранённым успешным ответом.
  Это кэш просмотренного, не установленный полный модуль. Обновление
  каталога доступно во время импорта, числа не зашиты.
- Веб применяет существующий безопасный разбор типографических блоков;
  Android читает текст нативно, исходные скрипты не исполняются.
  Внутренние ссылки/изображения статей и выбор диапазона через границу главы
  ещё требуют доработки. Карта различий нумерации не создаётся догадками.
- Публичная статистика подтвердила словарные архивы, но словарный API
  статей/карт отсутствует в проверенных маршрутах. Подключение таких
  материалов остаётся зависимым от отдельного серверного этапа.

Проверки этапа перечислены в PROJECT_STATUS.md; исходная таблица ниже
не описывает состояние после реализации этого этапа.

Наличие двух окон не означает готовность всей синхронизации из ТЗ.
Они открывают одну главу и исходный стих, но прокручиваются самостоятельно.
Сравнение по OSIS не заменяет карту соответствия разных систем нумерации:
оба загрузчика сейчас запрашивают тот же номер главы.

Веб-поиск (`searchLocalBible`) нормализует регистр и е/ё, проверяет наличие
каждого фрагмента через `includes`, читает сохранённые главы через `list()`
и прекращает выдачу после 30 результатов. Это не морфология и не точная форма:
запрос «Бог» может совпасть также с частью другого слова. Подсветки и полного
числа результатов нет. Общая нормализация удаляет диакритику; правила для
поиска стихов нужно отделить от правил поиска названий каталога.

## Подтверждённая серверная основа

В исходниках `D:/Projekte/BibleDesktop/routes/api.php` и контроллерах есть:

- `/api/commentary-modules` — публичные активные источники с числом статей;
- `/api/bible/books/{bookSlug}/commentaries` — вступления уровня книги;
- `/api/bible/books/{bookSlug}/chapters/{chapter}/commentaries` — материалы,
  затрагивающие главу, включая вступления к книге;
- `/api/verses/{verse}/commentaries` — материалы к стиху, включая диапазоны
  и более общий контекст;
- `/api/books`, `/api/books/{book}`, `/api/books/{book}/sections/{section}` —
  отдельные книги, постраничное оглавление и полный текст раздела.

Толкования хранят автора, источник, заголовок, текст, начало/конец диапазона,
связь с отдельной книгой. Каноническая привязка отделена от перевода Библии.
Книги могут иметь разделы без библейской привязки; они должны оставаться
доступными через библиотеку. Публичный раздел `/books` основного сайта API
не является готовым разделом в Bible App.

Нужно передавать выбранные `modules`: без них выдача толкований пустая.
До 30 источников на запрос. Книга/глава поддерживают limit/offset и total;
выдача стиха ограничена 100 статьями без пагинации/total. Отдельного запроса
по диапазону выбранных или видимых стихов сейчас нет. Не считать первые
100 статей полным результатом при большом корпусе.

По проверенным `PROJECT_STATUS.md` и `docs/MYBIBLE_DICTIONARIES.md` API:
есть загрузчик словарных SQLite-архивов, включая атласы; импорт статей,
карт и публичный словарный API ещё не подтверждены. Наличие архивов
не равно наличию опубликованных данных. Если текущий импорт уже добавит
это, после его завершения повторно проверить код и реальные ответы.

## Предлагаемый механизм чтения

1. **«Книги»**: каталог с поиском по названию/автору, карточка источника,
   оглавление со всеми страницами, чтение разделов по исходному порядку,
   предыдущий/следующий раздел, сохранение места. Не смешивать с выбором
   библейских книг. Раздел без привязки к Писанию также читается.
2. **«Словари»**: список источников, алфавит и поиск по одному/выбранным
   установленным словарям, полная статья, внутренние ссылки и история.
   Strong — специализированный словарь, обычные словари не заменяют его.
3. **Из Библии**: общий просмотр дополнительных материалов с текущей ссылкой,
   источниками и действиями «Кратко»/«Полностью». Толкования можно открыть
   к книге, главе, текущему стиху, выбранному диапазону или видимым стихам.
   На телефоне — выдвижная панель/отдельный экран, на широком экране — окно.
4. Текущий стих определяется верхним видимым стихом активного окна.
   Запросы обновляются с задержкой и отменой устаревших ответов. Смена
   источников не сбрасывает место Библии. Полный материал возвращает к нему.
5. Материал одного диапазона показывается один раз, с полной ссылкой его
   покрытия и автором. Вступления к книге/главе выделяются отдельно;
   не повторять их под каждым стихом и не обрезать текст по границе выбора.
6. Для выбранного диапазона нужен запрос пересечения канонических интервалов,
   включая переход между главами. Предлагаемая семантика: начало статьи
   не позже конца выбора и конец статьи не раньше начала выбора, плюс
   отдельно применимые материалы уровня книги/главы. Идентичность — ID
   статьи и версия модуля, а не совпадение заголовка/текста.

Сначала использовать текущие API книги/главы/стиха. Временное объединение
ответов по стихам возможно для малого выбора, с устранением дублей по ID,
но не заменяет полноценный запрос диапазона: возникает много запросов
и ограничение 100. Контракт диапазона/пагинации согласовать с проектом API
после импорта; не создавать вторую серверную систему здесь.

Слово открывает словарный поиск по явно доступным заголовкам/вариантам названий.
Точные привязки источника имеют приоритет. Совпадение слова не доказывает
географическое место или толкование: неоднозначные результаты требуют выбора.
HTML материалов очищать, скрипты исходных модулей не выполнять; Android
сохраняет нативный UI. Изображения и внутренние ссылки отображать через
проверенный контракт, сохраняющий принадлежность к модулю.

## Офлайн и состояние

Развивать существующие IndexedDB repositories и Android OfflineStore/
BibleContentSource. Добавить типы книг/статей/привязок, не копировать
толкование в каждую редакцию Библии. Хранить ID модуля, версию, статью,
канонические интервалы, метаданные и файлы. Новый контракт пакетов должен
включать состав, реальные размеры, контроль целостности и версию.
Кэш ранее открытой статьи не обозначать как установленный полный модуль.

Личные заметки/закладки остаются отдельными сущностями и не удаляются
при удалении материалов. Состояние чтения книги: module/book/section,
позиция и версия. Состояние окон Библии: перевод, ссылка, видимый стих,
смещение внутри стиха, режим/высоты/активное окно. Изменения текста требуют
проверки соответствия перед восстановлением пометок слов.

## Карты: сначала существующий атлас

Предлагается два вида просмотра, без замены имеющихся материалов:

- Историческая схема: исходное изображение, масштаб/перемещение/полный экран,
  точки с нормализованными координатами изображения, маршруты и подписи
  только при наличии достоверных данных. Изображение и метки преобразуются
  вместе; географическая точность для такой схемы не обещается.
- Географическая карта: координаты объектов, слои эпох/маршрутов, источник
  и степень определённости места. MapLibre GL JS и Native Android — кандидат
  после изучения данных. Android имеет API offline regions; вебу потребуется
  отдельная проверенная схема локального хранения картографических ресурсов.

Для каждого места нужен устойчивый ID, варианты названий, ссылки на Писание,
координаты/их тип и источник. Одноимённые объекты не объединять по названию.
Одно место может иметь несколько карт. Если у изображения нет координат,
открывать карту без выдуманной метки. Новые маршруты Павла создаются только
по проверенному источнику с указанием спорных мест. Генерация красивого
изображения сама по себе не создаёт достоверный библейский атлас.

Офлайн геокарта требует всех используемых ресурсов: тайлов, стиля,
шрифтов, значков и данных объектов. Права на локальную загрузку должны
быть подтверждены для выбранного источника. Сейчас новые зависимости
и поставщик тайлов не выбираются окончательно.

Документация кандидата: [ImageSource](https://maplibre.org/maplibre-gl-js/docs/API/classes/ImageSource/),
[Native Android offline](https://maplibre.org/maplibre-native/android/api/-map-libre%20-native%20-android/org.maplibre.android.offline/index.html).

## Следующие ограниченные задачи после импорта

1. Проверить опубликованные примеры: книга, глава, стих, диапазон внутри
   главы и через её границу; отдельная книга без привязки; словарь с внутренними
   ссылками; атлас с изображением/метками. Уточнить API, метаданные, нумерацию,
   полноту страниц, форматы и размер корпуса. Не фиксировать числа во время импорта.
2. Подключить чтение «Книг» на вебе и Android через существующее API.
3. Добавить контекстные толкования и выбор источников; затем диапазоны
   и сопровождение прокрутки. Проверить источник, дедупликацию и возврат.
4. Подключить обычные словари после появления проверенного API, затем
   установку модулей изучения офлайн. Стронга расширять через существующий Android UI.
5. Улучшать поиск/непрерывное чтение и управление окнами отдельными этапами
   исходного ТЗ. Пометки слов, подборки и заучивание — отдельные блоки.
6. Просмотр существующих атласов; географические слои — после проверки данных.

Каждая implementation-задача требует проверок обеих платформ: восстановление
места, отключённая сеть после установки, смена источников, диапазоны,
устаревшие ответы, пустой/частичный корпус, обновление модуля без потери
личных данных, телефон/планшет. Поиск дополнительно проверить на нескольких
полных переводах: время, память, полнота и различия точного/морфологического режима.
