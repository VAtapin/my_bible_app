# Техническое задание: «Церковнославянская азбука»

## 1. Статус документа

- Рабочее название продукта: **«Церковнославянская азбука»**.
- Семейство продуктов: **Bible Desktop**.
- Тип продукта: самостоятельное образовательное приложение с нативными
  клиентами и браузерной Web App.
- Целевые платформы: Android, iOS и Web.
- Android application ID: `com.bibledesktop.azbuka`.
- iOS bundle ID: `com.bibledesktop.azbuka`.
- Рабочий production URL Web App: `https://azbuka.bible-desktop.com`.
- Языки интерфейса первого выпуска: церковнославянский (по умолчанию), русский
  и немецкий.
- Основной режим работы: без обязательной регистрации; нативные клиенты —
  офлайн с первого запуска, Web App — в браузере без установки и офлайн после
  первого успешного открытия и кэширования.
- Статус: рабочая версия 1.1 для UX-проектирования, подготовки контента и
  реализации MVP.

Документ описывает новый самостоятельный продукт. Он не является модулем
`com.bibledesktop.myapp`, не должен смешиваться с основным приложением Bible
Desktop и выпускается отдельной карточкой в магазинах приложений.
Web App является третьим полноценным клиентом этого же продукта. Пользователь
должен иметь возможность открыть её по обычной HTTPS-ссылке и начать обучение,
не устанавливая PWA, расширение браузера или нативное приложение.

## 2. Назначение продукта

Приложение обучает чтению церковнославянских букв, надстрочных знаков, слов под
титлами и церковнославянской цифири с помощью коротких интерактивных уроков,
повторения и игровых упражнений.

Пользователь должен иметь возможность:

1. познакомиться с каждой буквой и увидеть её в проверенном живом тексте;
2. узнать название, чтение и варианты начертания буквы;
3. научиться распознавать надстрочные знаки и слова под титлами;
4. освоить единицы, второй десяток, десятки, сотни и большие числа;
5. закреплять материал в упражнениях с мгновенной обратной связью;
6. видеть прогресс по темам и продолжать обучение с последнего места;
7. пользоваться приложением непосредственно в браузере без установки;
8. пользоваться основными уроками и играми без подключения к интернету
   в нативных клиентах и после первого кэширования Web App.

Приложение не должно быть электронной копией существующего тренажёра. Оно
использует общеупотребимые образовательные механики, но получает собственную
архитектуру курса, тексты, задания, дизайн, графику, звук и программный код.

## 3. Целевая аудитория

### 3.1. Основные группы

- взрослые, начинающие изучать церковнославянский язык;
- прихожане, желающие увереннее читать богослужебные тексты;
- учащиеся воскресных школ и духовных учебных заведений;
- преподаватели, использующие приложение как вспомогательный тренажёр;
- пользователи Bible Desktop, интересующиеся церковнославянскими текстами;
- русскоязычные и немецкоязычные пользователи.

### 3.2. Ограничения аудитории

- интерфейс должен быть понятен без предварительного знания терминологии;
- обучение не должно предполагать постоянную помощь преподавателя;
- приложение не позиционируется как канонический учебник или замена
  систематическому курсу языка;
- сложные справочные пояснения отделяются от основного упражнения и открываются
  по запросу.

## 4. Продуктовые принципы

1. **Одно действие за раз.** На тренировочном экране пользователь решает одну
   понятную задачу.
2. **Мгновенная обратная связь.** После ответа сразу показываются результат,
   правильный вариант и короткое объяснение.
3. **Короткие занятия.** Базовая тренировка содержит 10 заданий, расширенная —
   20. Незавершённую сессию можно продолжить.
4. **Ошибки помогают учиться.** Ошибочный ответ возвращается в очередь
   повторения, но не блокирует дальнейшее обучение.
5. **Офлайн прежде всего.** В нативных клиентах первый учебный пакет
   устанавливается вместе с приложением. Web App сохраняет оболочку, контент и
   прогресс локально после первого успешного открытия.
6. **Спокойное оформление.** Интерфейс поддерживает сосредоточенное чтение и не
   превращает обучение в агрессивную игру.
7. **Доступность.** Все основные действия доступны крупными зонами касания,
   скринридером и без различения состояния только по цвету.
8. **Самостоятельность продукта.** Никаких WebView и встраивания существующего
   сайта в оболочку нативного приложения.
9. **Браузер без барьеров.** Web App запускается по ссылке без установки,
   регистрации и обязательного предложения «Добавить на главный экран».

## 5. Состав первого выпуска

### 5.1. Обязательные разделы MVP

- onboarding и выбор языка интерфейса;
- главный экран с продолжением обучения;
- карта церковнославянской азбуки;
- карточки букв с контекстными примерами;
- надстрочные знаки;
- слова под титлами;
- цифирь: единицы, второй десяток, десятки и сотни;
- тренировки с двумя вариантами ответа;
- тренировки «Верно / Неверно»;
- прогресс по темам;
- повторение ошибок;
- локальные настройки языка и оформления;
- офлайн-хранение учебных данных и прогресса.
- адаптивная Web App с функциональностью основного учебного сценария;
- сохранение браузерного прогресса и работа Web App без сети после первого
  успешного кэширования;
- PWA manifest и установка на главный экран как необязательная возможность.

### 5.2. Расширенный первый релиз

- большие числа;
- игра «Пятнадцать» с церковнославянской цифирью;
- упражнение на запоминание последовательности;
- интерактивные «соты»;
- система достижений и визуальный рост виноградной лозы;
- награды в виде проверенных цитат;
- церковнославянские часы;
- системная отправка карточки буквы или результата занятия;
- импорт обновлённых учебных пакетов.

### 5.3. Не входит в первый выпуск

- социальная сеть и публичные рейтинги;
- чат между пользователями;
- соревнования в реальном времени;
- обязательная регистрация;
- платные подписки;
- реклама;
- пользовательский редактор упражнений;
- автоматическое генерирование учебных текстов ИИ;
- копирование материалов, аудио или графики референсного приложения.

## 6. Информационная архитектура

На телефонах основная навигация размещается в нижней панели и содержит пять
разделов:

| Раздел | Назначение |
| --- | --- |
| Главная | продолжение урока, цель дня, прогресс и рекомендации |
| Азбука | буквы, их имена, чтение и примеры в контексте |
| Цифирь | отдельный алгоритм, таблицы и упражнения с числами |
| Тренировка | короткие упражнения и повторение ошибок |
| Профиль | достижения, статистика, язык и настройки |

На компактных экранах подпись активного пункта всегда видима. Вложенные экраны
используют стандартную кнопку «Назад», а не скрытое боковое меню. На широком
экране Web App допускается постоянная боковая навигация или верхняя панель, но
названия, маршруты и логика разделов должны совпадать с мобильными клиентами.

Каждый содержательный экран Web App имеет собственный устойчивый URL. Перезагрузка
страницы и открытие прямой ссылки не должны возвращать пользователя на главную.

## 7. Пользовательские сценарии

### 7.1. Первый запуск

1. Отображается фирменный splash screen.
2. Приложение открывается по-церковнославянски; пользователь при желании
   переключает интерфейс на русский или немецкий.
3. Приложение кратко объясняет три действия: изучить, потренироваться, повторить.
4. Пользователь выбирает уровень:
   - начинаю с нуля;
   - уже знаю некоторые буквы;
   - хочу изучать цифирь.
5. Разрешение на уведомления на этом этапе не запрашивается.
6. Создаётся локальный профиль, открывается рекомендуемый первый урок.

Onboarding можно пропустить. Все выбранные параметры позднее изменяются в
настройках. В Web App локальный профиль создаётся в браузере автоматически;
создание аккаунта, установка PWA и включение уведомлений не требуются.

### 7.2. Ежедневное продолжение

1. На главной отображается карточка «Продолжить».
2. Карточка показывает тему, последний завершённый шаг и ожидаемую длительность.
3. После урока отображаются результат, новые освоенные элементы и предложение
   повторить ошибки.
4. Прогресс сохраняется сразу после каждого ответа.

### 7.3. Свободное изучение буквы

1. Пользователь открывает карту азбуки.
2. Освоенные, изучаемые и ещё не открытые буквы различаются формой индикатора,
   подписью и цветом.
3. Нажатие открывает карточку буквы.
4. Пользователь читает проверенный пример и запускает тренировку по букве.

### 7.4. Тренировка

1. Перед началом показываются тема, число заданий и выбранный режим.
2. На экране находится одна карточка задания и две крупные кнопки ответа.
3. После ответа карточка показывает состояние «Верно» или «Нужно повторить».
4. Пользователь может открыть пояснение или продолжить.
5. После серии показываются результат, освоенные элементы и список ошибок.

## 8. Учебная программа

### 8.1. Модуль A. Азбука

- назначение церковнославянской азбуки;
- порядок букв от Аза до Ижицы;
- название и основной звук каждой буквы;
- начертание и допустимые варианты;
- различение визуально похожих букв;
- примеры из проверенных церковнославянских текстов;
- озвучивание названия, звука и выбранных примеров.

### 8.2. Модуль B. Надстрочные знаки

- ударения;
- придыхание;
- паерок;
- простое титло;
- буквенные титла;
- правила показа знаков в слове;
- задания на распознавание знака и его функции.

### 8.3. Модуль C. Слова под титлами

- назначение титла;
- распространённые сокращения;
- восстановление полного слова;
- распознавание ключевой буквы;
- чтение слова в контексте;
- тематические наборы слов без копирования чужой готовой подборки.

### 8.4. Модуль D. Цифирь

- принцип буквенной записи чисел;
- единицы;
- числа 11–19 и порядок знаков;
- десятки;
- сотни;
- составные числа;
- большие числа и специальные обозначения;
- преобразование из арабской записи в церковнославянскую и обратно.

### 8.5. Модуль E. Закрепление

- смешанное распознавание букв;
- звук → буква;
- название → буква;
- буква → числовое значение;
- число → церковнославянская запись;
- слово под титлом → полная форма;
- интервальное повторение ошибок.

## 9. Типы упражнений

Каждый тип задания реализуется как независимый движок с единым контрактом
входных данных и результата.

### 9.1. Выбор одного из двух

- один вопрос;
- два крупных варианта;
- варианты случайно меняются местами;
- правильность не должна угадываться по длине или оформлению кнопки.

### 9.2. «Верно / Неверно»

- показывается пара значений или утверждение;
- пользователь подтверждает или опровергает соответствие;
- переключатель сложности может включать близкие ошибочные варианты.

### 9.3. Соответствие

- буква ↔ название;
- буква ↔ звук;
- знак ↔ функция;
- церковнославянская цифирь ↔ арабское число.

### 9.4. Последовательность

- приложение подсвечивает последовательность элементов;
- пользователь воспроизводит её;
- длина увеличивается постепенно;
- звук можно отключить независимо от визуальной подсказки.

### 9.5. «Пятнадцать»

- поле 4 × 4;
- 15 элементов и одна свободная ячейка;
- элементы показывают церковнославянские числа;
- доступны перемешивание, число ходов, таймер без обязательного ограничения и
  возврат к сохранённой партии;
- победа определяется корректным порядком, а не временем.

### 9.6. Соты

- поле из шестиугольников;
- режим знакомства показывает карту букв и знаков;
- игровой режим использует последовательность или поиск требуемого элемента;
- форма сот не является обязательным элементом всех экранов и не должна мешать
  доступности.

## 10. Оценивание и повторение

### 10.1. Результат ответа

Для каждого ответа сохраняются:

- идентификатор задания;
- тема и учебный элемент;
- выбранный ответ;
- правильность;
- число попыток;
- время ответа без использования для наказания пользователя;
- дата следующего повторения.

### 10.2. Освоение элемента

Статусы элемента:

- `new` — ещё не изучался;
- `learning` — открыт, но результат нестабилен;
- `review` — требуется повторение;
- `mastered` — подтверждён серией успешных ответов.

Статус `mastered` присваивается не по одному ответу, а после успешных ответов в
разные дни или учебные сессии. Ошибка не обнуляет весь прогресс.

### 10.3. Повторение

MVP использует простое интервальное расписание: сразу после ошибки, затем через
один день, три дня, семь дней и тридцать дней. Интервалы являются конфигурацией
и могут корректироваться после пилота.

## 11. Мотивация и достижения

Основная визуальная метафора — рост виноградной лозы:

- семя — начат первый урок;
- росток — освоен первый модуль;
- листья — регулярные занятия;
- гроздь — завершён крупный раздел;
- зрелая лоза — завершён основной курс.

Прогресс не должен уменьшаться и не должен создавать чувство наказания за
пропущенный день. Серия дней показывается как дополнительная статистика, но её
потеря не уничтожает награды.

Допустимые достижения:

- первая освоенная буква;
- вся азбука;
- первая прочитанная фраза;
- единицы, десятки и сотни;
- серия без ошибок;
- возвращение к обучению;
- завершение всех повторений дня.

Цитаты-награды берутся только из проверенного редактором корпуса. Каждая запись
содержит источник и точную ссылку на произведение или место Писания.

## 12. Требования к экранам

### 12.1. Главная

- приветствие без обязательного имени;
- «Продолжить обучение»;
- повторения на сегодня;
- краткий прогресс курса;
- текущая стадия виноградной лозы;
- быстрый доступ к свободному изучению азбуки;
- ненавязчивое состояние офлайн/обновления.

### 12.2. Каталог курса

- модули представлены последовательными карточками;
- заблокированные темы объясняют условие открытия;
- пользователь может свободно открыть справочную часть любой темы;
- тренировочные уровни открываются после знакомства с материалом.

### 12.3. Карта азбуки

- все буквы помещаются в прокручиваемую или масштабируемую карту;
- на телефоне минимальная зона касания буквы — 44 × 44 pt/dp;
- фильтры: все, новые, на повторение, освоенные;
- надстрочные знаки размещаются отдельной группой;
- декоративная сетка не заменяет доступный линейный список для скринридера.

### 12.4. Карточка буквы

- крупное начертание;
- название;
- транскрипция или пояснение произношения;
- кнопка воспроизведения;
- числовое значение, если применимо;
- варианты начертания;
- краткая этимологическая или смысловая справка;
- 1–3 проверенных примера;
- перевод пояснения на язык интерфейса;
- действия «Потренироваться» и «Добавить в повторение».

### 12.5. Экран задания

- прогресс серии, например `4 из 10`;
- счёт правильных и требующих повторения ответов;
- одна смысловая задача;
- кнопка звука при наличии аудио;
- варианты ответа с зоной касания не меньше 48 dp/pt по высоте;
- текстовое и графическое подтверждение результата;
- кнопка «Далее» появляется после ответа или следующий вопрос открывается по
  явно настраиваемому автоматическому переходу.

### 12.6. Итог занятия

- количество верных ответов;
- элементы, которые стали освоенными;
- ошибки с правильными ответами;
- действия «Повторить ошибки», «Продолжить курс», «На главную»;
- награда, если она действительно получена;
- результат доступен скринридеру как связное сообщение.

### 12.7. Профиль и настройки

- язык интерфейса;
- язык пояснений, если позднее он отделяется от языка интерфейса;
- звук, голос и громкость относительно системной громкости;
- автоматическое воспроизведение;
- размер текста;
- светлая, тёмная и системная темы;
- управление загруженными учебными пакетами;
- экспорт и удаление локального прогресса;
- политика конфиденциальности, лицензии и сведения об источниках.

## 13. Визуальная система

Приложение использует семейство Bible Desktop, но имеет самостоятельный знак и
собственную образовательную символику.

### 13.1. Базовая палитра

| Роль | Цвет | Использование |
| --- | --- | --- |
| Основной синий | `#4A6B8A` | навигация, основные кнопки, активные состояния |
| Светлый синий | `#7DA1C2` | фокус, вторичные акценты, прогресс |
| Кремовый | `#EDE6D6` | учебные и декоративные поверхности |
| Основной фон | `#F7F5F1` | фон приложения |
| Золотой | `#B99A5A` | редкие акценты, награды, церковная символика |
| Успех | отдельный доступный зелёный | только подтверждение правильного ответа |
| Ошибка | отдельный доступный красный | только ошибка или требование повторения |

Жёлтые, розовые и бирюзовые полноэкранные фоны референсного приложения не
переносятся.

### 13.2. Типографика

- системный sans-serif — навигация, кнопки и пояснения;
- Georgia или согласованный антиквенный шрифт — заголовки;
- лицензированный церковнославянский шрифт — учебные символы и примеры;
- каждый выбранный шрифт должен корректно отображать буквы, титла, ударения и
  комбинируемые знаки на Android, iOS и в поддерживаемых браузерах;
- минимальный рабочий размер основного текста — 16 sp/pt.

### 13.3. Иконки и графика

- создаётся единый комплект собственных иконок;
- иконки не копируются из APK, сайта или скриншотов;
- все значимые иконки имеют текстовую подпись или accessibility label;
- новая иконка приложения должна быть узнаваемой рядом с Bible Desktop, но не
  повторять его основную иконку;
- виноградная лоза создаётся как отдельная серия оригинальных иллюстраций.

### 13.4. Адаптивность Web App

- обязательная ширина viewport: от 320 до 1920 CSS px;
- при ширине телефона используется тот же однофокусный сценарий, что в
  нативных клиентах;
- на планшете и desktop допускаются две колонки: навигация/прогресс и рабочая
  область;
- учебная карточка не растягивается на всю ширину большого монитора;
- клавиатурная навигация и видимый focus ring обязательны;
- hover не используется как единственный способ открыть действие;
- интерфейс учитывает safe area мобильных браузеров и экранную клавиатуру;
- browser chrome не должен скрывать основные кнопки или нижнюю навигацию.

## 14. Локализация

### 14.1. Разделение языков

Необходимо различать:

- язык интерфейса;
- язык учебного пояснения;
- церковнославянский учебный текст;
- транслитерацию и фонетическую подсказку.

Церковнославянские строки не считаются UI-локализацией и хранятся в учебном
контенте.

### 14.2. Первый выпуск

- церковнославянский интерфейс используется по умолчанию;
- русский интерфейс и русские пояснения;
- немецкий интерфейс и немецкие пояснения;
- одинаковый церковнославянский корпус для всех языков интерфейса;
- возможность переключить язык без потери прогресса;
- fallback на русский допускается только для служебной ошибки разработки и не
  должен появляться в release-сборке.

## 15. Аудио (после MVP)

В MVP озвучивание отключено. Системный синтез речи нельзя использовать для
церковнославянского текста: он неверно произносит Unicode-символы и надстрочные
знаки. Кнопка воспроизведения появится только после подготовки и редакторской
проверки собственного или лицензированного аудиопакета.

### 15.1. Требования

- собственные или лицензированные записи;
- единый диктор или согласованный набор дикторов;
- отсутствие фоновой музыки в учебных клипах;
- нормализованная громкость;
- форматы, поддерживаемые обеими платформами без дополнительного кодека;
- короткая задержка воспроизведения;
- работа офлайн;
- аудио не запускается неожиданно после сворачивания приложения.

### 15.2. Состав будущего аудиопакета

- названия всех букв;
- основные звуки;
- примеры произношения для выбранных букв;
- поясняющие аудиофрагменты не обязательны для MVP.

Для каждого файла фиксируются диктор, дата записи, лицензия, редакторская
проверка и соответствующий идентификатор учебного элемента.

## 16. Контентная модель

### 16.1. Основные сущности

`CourseModule`:

- `id`;
- `order`;
- локализованные название и описание;
- условия открытия;
- список уроков.

`Lesson`:

- `id`;
- `moduleId`;
- тип материала;
- локализованные инструкции;
- учебные элементы;
- рекомендуемая длительность;
- версия контента.

`LearningItem`:

- `id`;
- тип: буква, знак, слово, число или правило;
- церковнославянское отображение;
- нормализованная форма;
- варианты начертания;
- числовое значение;
- ссылки на аудио;
- локализованные пояснения;
- источники и редакторский статус.

`ExerciseTemplate`:

- `id`;
- тип упражнения;
- допустимый набор элементов;
- правило формирования правильного ответа;
- правило генерации отвлекающих вариантов;
- сложность;
- локализованная инструкция.

`Attempt`:

- локальный идентификатор;
- идентификаторы урока, задания и элемента;
- дата;
- результат;
- число попыток;
- длительность;
- версия контента.

`Progress`:

- элемент;
- статус освоения;
- серия успешных ответов;
- последняя попытка;
- следующее повторение;
- история изменения статуса.

### 16.2. Формат учебного пакета

Контент поставляется версионированным пакетом:

```text
manifest.json
content/
  courses.json
  lessons.json
  items.json
  exercises.json
  quotes.json
audio/
images/
fonts/
licenses/
  sources.json
  licenses.json
```

Пакет имеет номер схемы, версию содержимого, контрольные суммы файлов,
поддерживаемые языки и минимальную версию приложения. Приложение отклоняет
неполный или повреждённый пакет и продолжает использовать последнюю рабочую
версию.

## 17. Техническая архитектура

### 17.1. Общий подход

| Слой | Android | iOS | Web | Общая часть |
| --- | --- | --- | --- | --- |
| UI | Jetpack Compose | SwiftUI | Vue 3 + TypeScript | дизайн-токены, сценарии |
| Навигация | Navigation Compose | SwiftUI NavigationStack | Vue Router | карта маршрутов |
| Учебный движок | KMP use cases | KMP use cases | KMP JS package | Kotlin Multiplatform |
| Хранилище | платформенный драйвер | платформенный драйвер | IndexedDB | схемы и репозитории |
| Аудио | Android Media3/API | AVFoundation | Web Audio/HTMLMediaElement | метаданные |
| Сеть | Ktor Android | Ktor Darwin | Fetch/Ktor JS | контракты и ошибки |

WebView и Capacitor запрещены в целевой архитектуре нативных клиентов. Web App
является самостоятельным браузерным интерфейсом, а не содержимым, встроенным в
Android или iOS.

### 17.2. Общая Kotlin Multiplatform-логика

В общий модуль входят:

- модели курса и контента;
- загрузка и проверка учебного пакета;
- генератор упражнений;
- правила выбора отвлекающих вариантов;
- оценивание ответа;
- интервальное повторение;
- прогресс и достижения;
- локальные репозитории;
- импорт/экспорт профиля;
- Kotlin/JS export стабильного API учебного движка для Web App;
- тесты учебной логики.

UI, accessibility, платформенное воспроизведение звука, системная отправка,
браузерный service worker и уведомления остаются платформенными. Если часть
общей логики невозможно безопасно экспортировать в JavaScript, Web App
реализует тонкий TypeScript-адаптер и проходит те же контрактные fixtures; две
независимые версии правил оценивания не допускаются.

### 17.3. Минимальные платформы

- Android min SDK: 26;
- Android compile/target SDK: актуальная стабильная версия проекта, на момент
  подготовки документа — 37;
- JDK: 25;
- iOS: 16.0 и выше;
- Web: актуальная и предыдущая стабильная версии Chrome, Edge, Firefox и
  Safari; мобильные Chrome и Safari входят в обязательную матрицу;
- ориентация: portrait в MVP, планшетный adaptive layout без блокировки
  landscape после отдельной проверки игр.

### 17.4. Организация исходного кода

Продукт рекомендуется вести в отдельном Git-репозитории, чтобы не смешивать:

- идентификаторы приложений;
- ключи подписи;
- версии и release notes;
- store metadata;
- домен, Web App deployment и PWA metadata;
- учебные материалы и лицензии;
- CI/CD и доступы публикации.

Допускается повторное использование общих дизайн-токенов и проверенных
архитектурных решений Bible Desktop, но не копирование продуктовой логики между
приложениями через неявные зависимости.

### 17.5. Web App и PWA

Web App разрабатывается на Vue 3, TypeScript и Vite и публикуется как отдельный
клиент продукта. Рабочий адрес — `https://azbuka.bible-desktop.com`; окончательный
домен подтверждается перед настройкой production.

Обязательные свойства:

- первый экран открывается по HTTPS-ссылке без установки;
- весь основной учебный сценарий доступен в обычной вкладке браузера;
- запрос на установку PWA не блокирует интерфейс и не появляется автоматически
  при первом посещении;
- маршруты уроков и карточек поддерживают прямые ссылки и browser Back/Forward;
- `manifest.webmanifest`, service worker и иконки позволяют установить Web App
  по желанию пользователя;
- app shell, базовый учебный пакет, шрифты и аудио кэшируются после первого
  успешного открытия;
- прогресс, настройки и незавершённая сессия сохраняются в IndexedDB;
- обновление service worker не прерывает текущее занятие;
- новая версия активируется после завершения или явного подтверждения
  пользователя;
- Web Share API используется при наличии, иначе предлагается копирование ссылки;
- политика браузеров, запрещающая autoplay, соблюдается: первое аудио запускается
  только после действия пользователя;
- очистка данных сайта браузером может удалить локальный прогресс, поэтому это
  ограничение объясняется в настройках и при экспорте профиля.

SEO не должно усложнять учебный интерфейс. Допускается отдельная индексируемая
landing-информация, но само приложение остаётся быстрым SPA с корректными title,
description, Open Graph и language metadata для публичных маршрутов.

## 18. Локальное хранение и офлайн-режим

В нативных клиентах без сети должны работать сразу после установки, а в Web App
— после первого полного открытия и успешного кэширования:

- onboarding;
- весь базовый курс;
- карточки букв и правил;
- упражнения;
- игры;
- прогресс, достижения и настройки.

Локально хранятся:

- встроенный учебный пакет;
- загруженные обновления пакета;
- профиль и настройки;
- попытки и прогресс;
- незавершённое занятие;
- партия «Пятнадцать»;
- очередь необязательной синхронизации.

Web App хранит учебные данные и прогресс в IndexedDB. Cache Storage используется
для версионированных статических ресурсов, шрифтов и аудио. `localStorage`
допускается только для небольших несекретных настроек и не является основным
хранилищем прогресса.

Обновление контента выполняется атомарно: новый пакет сначала загружается и
проверяется, затем становится активным. При ошибке используется предыдущая
версия.

## 19. Сервер и синхронизация

MVP не требует учётной записи или прикладного сервера для основного обучения.
Web App требует только статического HTTPS-хостинга и возможности выдавать
версионированные учебные пакеты.

Production-сборка Web App разворачивается в Plesk с Node.js 22. Deployment
должен использовать проектный скрипт, атомарную смену build-каталога, корректный
SPA fallback и заголовки кэширования: HTML и service worker не кэшируются
навсегда, а ресурсы с content hash могут кэшироваться длительно. После
deployment выполняется HTTP smoke test главной страницы, прямого маршрута урока,
manifest и service worker.

Опциональные endpoints последующих версий:

- проверка версии учебного пакета;
- загрузка подписанного пакета;
- резервная копия прогресса пользователя;
- синхронизация между устройствами;
- удалённая конфигурация без изменения правильных ответов задним числом.

Если синхронизация подключается к Bible Desktop API, она должна иметь отдельный
namespace, версионированный контракт и независимые права доступа.

## 20. Конфиденциальность и безопасность

- учётная запись в MVP не требуется;
- приложение не содержит рекламных SDK;
- сторонняя аналитика по умолчанию не подключается;
- учебный прогресс хранится локально на устройстве или в профиле браузера;
- передача диагностических данных возможна только после понятного согласия;
- в диагностике запрещены тексты из пользовательских заметок и иные личные
  данные;
- сетевой клиент принимает только HTTPS;
- учебные пакеты проверяются по контрольной сумме и подписи;
- секреты, ключи подписи и store credentials не хранятся в Git;
- пользователь может удалить весь локальный прогресс с подтверждением;
- политика конфиденциальности доступна до включения необязательной синхронизации.

## 21. Accessibility

Обязательные требования:

- поддержка TalkBack и VoiceOver;
- поддержка браузерных скринридеров и полной клавиатурной навигации;
- логичный порядок фокуса;
- доступные названия церковнославянских символов;
- минимальная зона касания 44 × 44 pt на iOS, 48 × 48 dp на Android и
  44 × 44 CSS px в Web App;
- результат ответа обозначается текстом, иконкой и цветом;
- контраст WCAG 2.1 AA для рабочего текста и контролов;
- поддержка увеличенного системного шрифта без потери функций;
- отключение необязательных анимаций при Reduce Motion;
- тактильная обратная связь имеет визуальный и звуковой эквивалент;
- аудио не является единственным способом получить учебную информацию;
- игры имеют неограниченный по времени режим.
- семантические landmarks, заголовки, live regions и управление фокусом после
  смены маршрута проходят отдельную web-проверку.

## 22. Производительность и надёжность

- холодный запуск на поддерживаемом устройстве: целевое значение до 2 секунд;
- открытие следующего локального задания: до 150 мс без учёта анимации;
- воспроизведение локального аудио: субъективно без заметной задержки;
- сохранение ответа выполняется до перехода к следующему заданию;
- аварийное завершение не должно терять уже подтверждённые ответы;
- размер базового пакета определяется после записи аудио, целевой предел APK/AAB
  и IPA устанавливается перед beta-релизом;
- нативные приложения корректно работают без сети с первого запуска;
- Web App достигает LCP до 2,5 с, INP до 200 мс и CLS до 0,1 на целевых
  устройствах при типовом соединении;
- основной интерфейс Web App остаётся работоспособным при медленной загрузке
  аудио, а аудиофайлы подгружаются независимо;
- повторное открытие закэшированной Web App доступно без сети;
- ошибки обновления контента не блокируют встроенный курс.

## 24. Критерии готовности MVP

MVP считается готовым, когда одновременно выполнены условия:

1. Android, iOS и Web проходят один и тот же основной учебный сценарий.
2. Доступны русский и немецкий интерфейсы без смешивания языков.
3. Web App открывается по production HTTPS-ссылке и работает без установки,
   регистрации и обязательного PWA prompt.
4. Базовый курс работает без сети после установки нативного клиента или после
   первого успешного кэширования Web App.
5. Все буквы открываются, корректно отображаются и имеют проверенные карточки.
6. Аудио воспроизводится и корректно останавливается.
7. Доступны модули азбуки, надстрочных знаков, титл, единиц, второго десятка,
   десятков и сотен.
8. Работают выбор из двух, «Верно / Неверно» и повторение ошибок.
9. Прогресс сохраняется после завершения приложения или закрытия вкладки.
10. Прямые web-маршруты, browser Back/Forward и обновление страницы работают.
11. Нет блокирующих дефектов accessibility.
12. Учебный корпус и лицензии прошли редакторскую и юридическую проверку.
13. Release-сборки подписаны отдельными ключами продукта.
14. Подготовлены privacy policy, store/PWA metadata, скриншоты и инструкции
    восстановления ключей.

## 25. Этапы реализации

### Этап 0. Подготовка

- отдельный репозиторий и идентификаторы;
- подтверждение названия;
- прототип церковнославянского шрифта на Android/iOS/Web;
- схема контента;
- список источников и лицензий;
- сценарии записи аудио;
- UX wireframes ключевых экранов.

### Этап 1. Вертикальный прототип

- onboarding;
- главная;
- 5–10 карточек букв;
- один урок;
- выбор из двух;
- звук;
- локальный прогресс;
- Android, iOS и Web на общем учебном движке;
- первый deploy Web App на staging с прямыми маршрутами и service worker.

### Этап 2. Полный базовый курс

- вся азбука;
- надстрочные знаки;
- слова под титлами;
- цифирь до сотен;
- русский и немецкий контент;
- повторение и итог занятия;
- адаптивная Web App и проверенный браузерный offline-режим.

### Этап 3. Игры и мотивация

- «Пятнадцать»;
- последовательности;
- соты;
- виноградная лоза;
- достижения и проверенные цитаты;
- церковнославянские часы.

### Этап 4. Release readiness

- accessibility audit;
- beta-тестирование с преподавателями и начинающими;
- исправление неоднозначных заданий;
- подпись и резервное хранение ключей;
- store metadata и privacy labels;
- Web App metadata, CSP/security headers и production deployment runbook;
- финальный Android/iOS/Web QA;
- публикация поэтапным rollout.

## 26. Юридические и редакторские ограничения

Референсные APK, сайт и карточка магазина используются только для анализа
общих сценариев. Запрещается переносить без документированного разрешения:

- исходный или декомпилированный код;
- готовые базы заданий;
- точную структуру и подбор защищённой базы данных;
- тексты справки и описаний;
- изображения, иконки и анимации;
- аудиозаписи;
- названия уникальных достижений и авторские формулировки;
- идентичное расположение и оформление экранов.

Для каждого внешнего материала в нашей базе фиксируются источник, автор,
лицензия, дата проверки и допустимый способ использования. Общеупотребимая
идея упражнения не считается разрешением копировать конкретное наполнение.

Перед публикацией выполняются:

- проверка названия и товарных знаков;
- проверка лицензии церковнославянского шрифта;
- проверка прав на аудио и иллюстрации;
- проверка переводов и цитат;
- подготовка собственного пользовательского соглашения и privacy policy;
- при необходимости регистрация собственной программы и базы материалов.

## 28. Принятые по умолчанию решения

До отдельного изменения требований действуют следующие решения:

- продукт создаётся отдельно от `com.bibledesktop.myapp`;
- application/bundle ID — `com.bibledesktop.azbuka`;
- код размещается в отдельном репозитории;
- UI полностью нативный;
- Android и iOS используют нативный UI, Web App — Vue 3/TypeScript;
- общая логика реализуется на Kotlin Multiplatform с JS export для Web App;
- первый релиз работает без регистрации и рекламы;
- базовый курс доступен офлайн;
- Web App полностью работает в браузере без установки, а PWA является только
  дополнительным способом запуска;
- рабочий URL Web App — `https://azbuka.bible-desktop.com`;
- интерфейс первого выпуска — церковнославянский по умолчанию, русский и
  немецкий по выбору;
- референсное приложение не является источником копируемых материалов;
- публикация выполняется отдельно в Google Play, RuStore и App Store, а Web App
  разворачивается на собственном HTTPS-субдомене после прохождения release QA.
